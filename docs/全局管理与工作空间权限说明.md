# 全局管理与工作空间权限

## 角色与入口

| 角色 | 后端值 | 前端入口 | 管理范围 |
| --- | --- | --- | --- |
| 全局管理员 | `ADMIN` | `/admin/overview` | 全局总览、空间状态、空间管理员与全站资源／安全／日志治理 |
| 工作空间管理员 | `TENANT_ADMIN` | `/workspace-admin`，文件入口 `/` | 本空间成员、邀请与审批，以及已授权云盘的文件上传与管理 |
| 普通用户 | `USER` | `/` | 自己获授权的云盘、课程资料与 Agent 功能 |
| 访客 | `GUEST` | `/` | 仅按访客授权访问；不能登录后台 |

现有内置 `ADMIN` 账号继续作为唯一内置全局管理员，不迁移或重置密码。全局管理员通过“空间人员 → 选择工作空间 → 新增空间管理员”创建该空间管理员；新建页预设并固定角色及空间，不存在／停用空间不可保存。公众注册也可选择创建自己的新空间，并成为该空间管理员，邮箱验证通过后无需人工审核；公众注册不能成为全局管理员。成员使用邀请码可直接加入，凭空间名称申请则由对应空间管理员审核。工作空间管理员不能创建其他管理员、提升角色或跨空间操作。

本版继续使用现有 Spring Boot、Vue 与 Sa-Token 后台，按若依常见的“角色、菜单、业务服务分层”思路组织，不直接导入若依项目或另建第二套账号系统。这样现有登录、存储授权和历史数据保持一致。

## 全局总览

`/admin/overview` 已扩展为可操作的站点总览：

- 工作空间、成员账号、空间管理员、存储源、分享、有效待确认 Agent 任务的全局统计。
- 已停用空间、待加入申请、过期分享、异常 Agent 任务与自动化计划提醒，以及相关管理入口。
- 最近 7 天成功／失败登录趋势、24 小时汇总、最近 8 条登录记录及统计时区。日志关闭时明确说明只统计历史已记录数据，不把日志量当作站点访问量。
- 当前 Java 进程运行时长、JVM 堆内存、数据库类型与一次数据库探测耗时。不是服务器总内存、文件容量或全站平均请求延迟。
- 全部空间的名称／ID 搜索、状态筛选、分页、负责人账号 ID、成员／管理员／待加入／存储源数量。行“管理”通过独立 `workspaceId` 参数精确定位，不用模糊 ID 搜索代替定位。

接口保留原有 `workspacePreview` 字段兼容旧调用；新界面使用 `GET /admin/overview/workspaces` 分页，不再只看前 20 个空间。`keyword` 最长 100 字符，`page` 为 1–10000，`pageSize` 为 1–100；`enabled` 可选，`workspaceId` 为可选正整数。接口与服务均先检查全局管理员权限。

成员“账号启用”与空间启用状态分别统计，不表示用户在线，也不代表所属空间必然可用。待加入和已拒绝账号不计入正式账号启停分项；成员总数包括这些已注册账号。工作空间管理支持分页、提交后的筛选条件、名称修改与启停，空间名称上限统一为 80 字符，停用前会提醒影响范围，停用不删除文件。

总览不返回成员私人文件、邮箱、密码、登录请求 IP、Agent 标题／步骤／结果或邀请码；只返回必要汇总及最近登录的账号尝试值、时间、成功标记。全局管理员不能从此页面代替成员确认、执行或重试 Agent 任务。待加入申请仍由相应空间管理员审核。

登录日志管理仅返回 `id/username/createTime/ip/userAgent/referer/result`，不查询或返回历史密码字段；已移除密码筛选与显示。排序字段和方向采用白名单，分页有上限，空日期选择不筛选，反向日期拒绝。通用业务拒绝与参数格式错误不再误报 HTTP 500；真正的系统异常仍保持服务器错误响应。

## 工作空间管理员操作

### 界面与职责收纳

超级管理员常驻菜单只有“全局总览、工作空间、空间人员”。“全局资源治理”“站点与安全”“日志与诊断”默认折叠，进入组内页面会自动展开；桌面与手机共用相同菜单和展开状态。“返回云盘”和“退出登录”保持可见。访客权限、默认权限模板与内置全局账号设置保留在折叠安全组内。

空间人员页面使用分页空间目录和安全的轻量账号接口，不再一次加载所有用户及各自存储授权。当前空间的管理员先展示，普通成员默认折叠，展开后才分页查询。普通成员在全局页只读展示状态／归属，不再重复提供新增、复制、删除、启停和审批按钮；日常成员操作在对应空间控制台进行。切换空间会取消旧请求，避免上一空间数据覆盖当前视图。

普通管理员控制台提供“我的文件／上传文件、学习资料、自动化任务”入口，复用现有业务页面。成员管理可折叠；“邀请与加入申请”默认折叠，首次展开才加载。无存储源时正常结束加载并给出配置提示，不再卡在未完成的 Promise，也不会误导普通管理员进入全局存储配置。

### 本空间成员

`/workspace-admin` 显示本空间的普通用户数量、启用人数和存储源数量；成员列表支持用户名/昵称搜索和分页（每页 20 人）。管理员可以创建普通用户、启用或停用本空间普通用户。创建时仅继承管理员当前在同一工作空间的存储源授权和默认权限；不能选择其他工作空间的存储源，不能自定新账号角色。初始密码由管理员安全地交给成员，成员登录后自行修改。

工作空间管理员不能进入 `/admin/**` 全局接口，也不能修改其他工作空间的用户、同空间其他管理员、内置全局管理员或访客账号。停用成员后，已有会话也会在下一次请求时被后端拒绝。工作空间停用后，其管理员和成员均无法继续使用登录功能。

当前工作空间管理员**不负责**存储源连接配置、全局安全策略、用户角色晋升、跨空间迁移和成员删除；这些高风险操作只在全局后台进行。前端隐藏菜单只是辅助体验，真正的边界由后端实时角色与工作空间检查保证。

### 空间共享云盘

新注册的空间和全局后台新建的启用空间会自动开通本地“空间共享云盘”。物理目录以不可变空间 ID 隔离为 `受管根目录/tenant-<ID>`，存储标识为 `workspace-<ID>`。这是空间共享文件，不是个人私有目录。管理员可按文件授权上传、新建目录、重命名、移动、复制及删除；新成员／审批通过成员按现有逻辑继承本空间管理员的授权。待审、已拒绝、访客和其他空间不会获得新共享盘权限。

旧空间使用“工作空间 → 开通共享云盘”按钮，仅全局管理员有权调用。重复开通不重复创建，也不恢复主动撤销的授权或覆盖既有权限。未知非空目录、同名自定义存储、被修改的受管路径、符号链接及停用空间均拒绝自动接管。注册失败会回滚数据库与新存储上下文，仅清理由本次创建且仍为空的目录，不递归删除文件。

`STUDENT_CLOUD_WORKSPACE_STORAGE_ROOT` 可以指定受管根目录；默认使用项目日志数据目录旁的 `workspaces`。Docker 建议设置为 `/data/workspaces` 并持久挂载对应目录，容器用户必须有写权限，备份时同时备份该目录和数据库。现有单文件上传上限不等于空间总容量配额：本次没有增加硬性的空间容量限制，服务器仍需磁盘监控。

## 部署与数据库

`user.role` 现有字段为 `VARCHAR(32)`，能直接保存 `TENANT_ADMIN`，这次不需要新增数据库迁移或重建数据库。部署新版本前仍应备份数据库和上传文件。升级后使用现有全局管理员登录，在用户管理中手动指定工作空间管理员；不会自动提升任何旧账号。

相关接口：全局 `GET /admin/overview`、`GET /admin/overview/workspaces`、`GET /admin/overview/workspaces/{tenantId}/users`、`POST /admin/overview/workspaces/{tenantId}/storage`、`GET /admin/login/log/list`；工作空间 `GET /api/workspace-admin/summary`、`GET /api/workspace-admin/members`、`POST /api/workspace-admin/members`、`POST /api/workspace-admin/members/{id}/enabled?value=true|false`。工作空间接口即使被直接调用，也会逐次校验当前账号、角色、空间状态及目标用户归属。

全局空间人员分页接口仅允许 `TENANT_ADMIN`／`USER`，可筛选角色、账号 ID／用户名／昵称／邮箱，`keyword` 最长 100，分页上限同空间目录。它只查询必要账号字段和审核状态，不返回密码、存储连接、路径、邀请码或私人内容；不逐用户装配存储详情。

## 验证

后端集成测试默认使用独立临时 SQLite 数据库；也支持严格限定的本地 `student_cloud_role_test_*` MySQL 测试库。三套 HTTP 测试分别使用不同库，不覆盖业务库。测试覆盖角色登录、全局接口拒绝、跨空间隔离、内置账号保护、禁用已有会话、统计口径、搜索转义、分页边界及日志安全投影。前端测试覆盖角色边界、数据格式化、查询参数和旧响应防护；另需浏览器实际验证页面交互。
