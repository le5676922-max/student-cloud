# 超级管理员控制台完善与测试

验证日期：2026-10-03。本文记录本次改动与实际验证范围，不表示所有外部存储厂商、真实 SMTP 或在线模型都已重新测试。

## 已完成的功能

### 按工作空间管理人员

- “空间人员”使用分页空间目录，选中空间后先显示空间管理员，普通成员在下方默认折叠，展开后才查询。
- 管理员与成员分别分页、搜索，支持账号 ID、原有账号、昵称和邮箱；明确显示待审核、已拒绝、启用、停用状态。
- 全局成员区域只读，不再重复提供成员创建、启停、复制、删除或审批按钮；这些日常操作保留在对应工作空间管理员控制台。
- 全局管理员可新增和维护空间管理员；新增入口固定角色与所属空间，只有该空间启用且有效时才可保存。
- 总览跳转通过 `workspaceId` 精确定位空间，随后主动搜索会解除初始 ID 限制，避免无法切换其他空间。
- 切换空间、修改筛选和收起成员区域会取消旧请求，避免旧空间数据覆盖新空间。

### 全局导航与职责收纳

- 常驻菜单：全局总览、工作空间、空间人员。
- 默认折叠菜单：全局资源治理、站点与安全、日志与诊断。直接进入组内页面会自动展开。
- 访客权限、默认账号权限模板和内置全局账号设置仍然保留，没有删除必要的全局安全功能。
- 桌面和移动端共用菜单与展开状态，折叠按钮支持键盘；返回云盘与退出登录常驻。
- 内置账号编辑路由按用户 ID 重建表单，防止访客与全局管理员切换后仍显示上一账号的数据。

### 普通管理员存储文件

- `/workspace-admin` 提供“我的文件 / 上传文件”、学习资料和自动化任务入口，复用现有云盘，不新增第二套上传系统。
- 成员管理可折叠；邀请与加入申请默认关闭，首次展开才加载。
- 新注册空间和后台新建的启用空间自动开通本地“空间共享云盘”；管理员可按授权上传、建目录、重命名、移动、复制及删除。
- 老空间由全局管理员在“工作空间”中点击“开通共享云盘”。重复开通不重复创建，也不恢复被主动撤销的权限。
- 全局新增空间管理员时，表单默认启用该空间受管共享盘的基础文件权限，不自动授权其他空间、自定义存储或已停用存储。
- 待审核、已拒绝、访客和其他空间账号不会获得新共享盘权限。新成员和审核通过成员继续按既有逻辑继承本空间管理员授权。
- 共享盘目录按不可变空间 ID 隔离；未知非空目录、自定义同名源、被改动的受管路径和符号链接不自动接管。事务失败只清理由本次创建且仍为空的目录，不递归删除文件。

这是空间共享文件，不是每个成员的独立私人目录。本次没有增加空间总容量硬配额。

### 同轮修复

- 空存储列表正常完成加载，清除旧文件与权限，按角色显示正确的开通提示，不再卡住或跳转 `/undefined`。
- 文件操作无授权返回 HTTP 403，而不是 HTTP 500，原业务错误码保留。
- 匿名签名下载实时检查存储源和所属空间；停用后，原有效下载链接也不能继续读取文件。
- 登录日志安全投影不查询或返回密码，排序和分页参数受限；总览只提供必要统计，不展示或执行成员私人 Agent 任务。
- 上传框保留原插图，添加局部 `80px × 72px` 宽高限制。原 SVG 自带约 `782px × 702px` 尺寸，单独设置字体大小无法限制它；不改变其他插图和小芽。

## 使用与部署注意

本地前端入口：`http://127.0.0.1:5173/login`；后端：`http://127.0.0.1:8080`。以现有全局管理员登录进入“空间人员”查看新页面，不需要重建数据库或重置账号。

旧空间尚无存储时，进入“工作空间 → 开通共享云盘”；若已主动撤销管理员授权，应由全局管理员检查该管理员授权，而不是重复开通来恢复权限。

Docker 部署时建议设置 `STUDENT_CLOUD_WORKSPACE_STORAGE_ROOT=/data/workspaces` 并持久挂载该目录，容器用户需有写权限。数据库和共享文件必须一起备份，仍需监控宿主机磁盘容量。完整角色边界见《全局管理与工作空间权限说明》。

本轮没有提交或推送 Git，没有改动小芽。临时测试服务验收后停止，独立测试库和证据保留，业务前后端保持运行。
