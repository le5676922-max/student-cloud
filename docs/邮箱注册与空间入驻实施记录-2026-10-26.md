# 邮箱注册与空间入驻实施记录

日期：2026-10-26 · 新 Spring Cloud 后端开发版本 `0.1.0-SNAPSHOT`

本轮在账号与平台服务接通公开邮箱注册、找回密码和工作空间加入，并修复影响现有前端的契约错误。原主题、页面布局和角色动画保留，线上网站与旧数据库未改动。

## 新功能与规则

| 范围 | 结果 |
| --- | --- |
| 空间管理员注册 | 邮箱验证，系统分配唯一账号，直接创建启用空间；不需要审核，不允许公开注册全局管理员 |
| 成员邀请码注册 | 同事务验证邀请、计入使用次数并启用空间成员；不自动授予云盘/课程权限 |
| 成员空间名称注册 | 保持禁用并生成待审核申请；其它空间管理员看不到该申请，普通启用操作不能绕过审核 |
| 邀请管理 | 多次创建、到期/人数限制、长期有效/不限人数、撤销，原文只返回一次 |
| 邮箱验证码 | 6位、10分钟、冷却与每日/错误次数限制、HMAC摘要、用途隔离、同事务一次性消费 |
| 找回密码 | 邮箱证明后更新摘要并撤销旧会话；保留停用及待审批状态 |
| 找回隐私 | 已注册与未注册邮箱共享冷却/次数预算；未知邮箱不发信且无可用证明，公开接口不返回供应商投递及激活结果 |
| SMTP | 独立配置、TLS/认证与超时、无密码或验证码日志，默认关闭，未配置时如实停用邮件入口 |

新增平台 V3邮件、V4入驻、V5资料迁移，保留已有 V1/V2校验历史不变。数据仍由 platform 自有库管理，未让内容/智能服务直接读取身份表。

## 前后端兼容修复

- 全局配置补上 `installed`，避免文件布局误认为尚未初始化而循环跳转。
- 无验证码的登录模式返回前端支持的 `off`，不再返回无法识别的 `none`。
- 成员分页返回 `{items,total,page}`，显示昵称及 `ACTIVE/PENDING/REJECTED` 状态。
- 昵称及审批状态按页批量读取，100名成员也只做一次补充查询；空页不执行补充查询，避免 N+1。
- 管理员手工创建成员保留可不填邮箱的已有流程，不把未验证邮箱写成已验证。
- 工作空间概览通过内容服务获取真实存储数量；依赖故障时返回不可用标识，前端显示“—”，不伪造为0。
- 初始化页的密码8–128、账号64字符限制与后端统一。
- 邀请列表正确显示空有效期和空人数上限。

## 实际执行

| 检查 | 结果 |
| --- | --- |
| 账号定向测试 | 41项通过，失败0、跳过0：账号管理5、验证码12、注册/找回13、入驻7、批量成员查询4；包含一次性消费、事务回滚、错误次数、邀请最后名额竞争、审批及重置隔离 |
| 相关前端回归 | 登录流程、注册、找回、工作空间页面5个既有文件合计59项通过，失败0、跳过0 |
| Maven构建 | 15子模块跳过测试打包通过，依赖边界规则通过；不是整个测试套件的通过声明 |
| 真实数据库 | 临时MySQL8.4.11三个独立库，平台5份迁移成功，内容与智能仍各自持有数据 |
| SMTP/HTTP | 四个独立服务进程经Gateway，使用只接收合成邮箱的本地SMTP，注册/找回投递和接口流程通过 |
| 管理员注册 | 邮箱及账号ID均可登录，角色为普通空间管理员，无审核记录 |
| 成员审批 | 邀请直接加入；名称加入登录被拒绝；跨空间审核失败；普通启用绕过审批失败 |
| 密码找回 | 待审核成员重置后仍不能登录，批准后可登录；已登录成员重置后旧Token被其它服务拒绝 |
| 管理兼容 | 无邮箱手工创建成员、昵称、分页与实际工作空间数量通过 |
| 故障 | 未注册邮箱通用响应、不发送其它资料；模拟邮件失败503及冷却429；内容服务停止后统计为未知 |

没有执行压测或完整浏览器/全站测试，没有发送真实QQ邮件，没有部署到ECS。检查结束后临时服务、SMTP接收器与MySQL停止，临时凭据删除。

后续找回隐私修复先由7项回归重现，再统一通过41项账号定向测试；先前MySQL/SMTP检查不等于重新验证这次修复。当前SMTP仍同步执行，投递耗时可能形成时延侧信道，不能声称已消除所有邮箱枚举方式。后续可使用有界异步邮件任务进一步隔离该差异。
