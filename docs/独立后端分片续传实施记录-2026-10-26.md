# 独立后端分片续传实施记录

## 范围与配置

实现位于 `backend-independent/cloud-drive-application` 和 `cloud-content-service`，没有引用旧后端的续传服务或 V71 表。数据库脚本为 `db/independent-uploads-schema.sql`，由内容服务迁移版本9注册。前端仅在 `globalConfig.accountModel === 'independent'` 时选择独立协议，并校验能力响应的 `protocol: independent-v1`。

启用前须准备已存在、受服务账号控制的私有目录，配置 `SC_UPLOAD_STAGING_ROOT`。该目录必须与 `SC_MANAGED_STORAGE_ROOT` 和 `SC_COURSE_STORAGE_ROOT` 互不包含，不接受路径祖先中的符号链接或目录重定向。容器部署应使用内容节点独占的持久卷，Linux 权限应为700。默认未配置暂存目录时能力接口返回关闭，沿用普通上传。

`SC_CONTENT_NODE_ID` 是持久化节点标识，重启后必须保持不变。会话绑定账号、空间、授权快照和节点；其他节点返回409，不能把两个节点上的同名路径当成共享文件。当前没有跨节点续传、节点自动接管或对象存储多段上传。

## 实际协议

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/uploads/resumable/capabilities` | 登录头鉴权、目录授权与真实能力 |
| POST | `/api/uploads/resumable/init` | 文件名称、目标目录、大小、分片SHA256清单及清单摘要 |
| GET | `/api/uploads/resumable/{id}` | 收据及 `receivedChunks`、`missingChunks` |
| PUT | `/api/uploads/resumable/{id}/chunks/{index}` | 原始二进制分片及 `X-Upload-Chunk-SHA256` |
| POST | `/api/uploads/resumable/{id}/complete` | 完整校验后提交；完成收据幂等 |
| DELETE | `/api/uploads/resumable/{id}` | 取消尚未发布的任务，仅删除私有暂存 |

全部接口沿用严格登录头鉴权，URL和查询参数不携带会话凭据。前端独立分支不发送旧目录密码头。浏览器摘要校验依赖安全上下文，公网必须使用HTTPS。

浏览器从8MiB开始选择分片上传，分片固定4MiB，单文件最多50MiB。一个账号最多3个未完成任务、100MiB声明大小的暂存预留；实例总预留最多1GiB、最多1000条收据。每账号每节点最多2个处理请求，节点IO最多4路；内存使用16KiB缓冲。哈希冲突以外的内容误配会被逐片SHA256拒绝。

声明大小预算不是磁盘峰值：分片与合并副本合计可能使用约2倍预留；最终提交还会经过普通上传和文件内核的暂存，因此还需为最终云盘和其临时文件保留磁盘空间。完成收据先落库，私有分片成功清理后才释放预留；清理失败不会假装释放容量。

会话有效期固定24小时，不随分片请求延长。后台每15分钟有界清理本节点过期记录，初始化也执行有界清理。清理只处理身份绑定的会话目录和本服务创建的文件，绝不删除云盘目标路径。目录身份校验失败时保留记录和预留以便核查。

## 恢复与完成边界

分片索引有唯一约束，会话处理使用持久化尝试令牌和比较更新。分片先写入独立尝试文件，摘要与长度通过后才记录收据；进程重启后重新选择原文件会匹配同一未完成会话，只上传缺块。没有落下收据的尝试文件会在下一次独占处理时有界回收。

最终提交会重新检查授权快照、目录状态和普通上传的容量限制，然后先持久化 `COMPLETING`，再调用独立 `MountService.upload`。目标同名不覆盖。已进入发布窗口但结果未知的任务保持 `COMPLETING`，任何重试只查询状态，不自动重新发布，也不删除目标文件。最终成功收据为 `COMPLETED`，重复完成返回同一结果。

已完成会话不会成为后续初始化的去重目标：原文件被删除后重新上传必须创建新会话，不能因历史收据而错误跳过上传。对已有同名目标的新初始化仍返回冲突。
