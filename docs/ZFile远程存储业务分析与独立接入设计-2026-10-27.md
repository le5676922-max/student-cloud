## 2. 业务入口与状态流

### 2.1 旧版配置保存与初始化

`StorageSourceController.saveStorageItem` 接收 `POST /admin/storage`，委托 `StorageSourceService.saveStorageSource`；详见 [Controller 第 125–129 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/controller/base/StorageSourceController.java#L125)。服务中的实际顺序如下：

1. 要求系统管理员，判断新增或更新；更新时检查管理权限并销毁旧存储上下文。
2. 保存存储源基本信息，将参数 DTO 转换为键值配置并替换数据库配置。
3. 构造初始化 DTO，创建相应类型的 prototype 服务，填入参数，执行 `init()` 和 `testConnection()`。
4. 成功后注册 `storageId → service`、`storageKey → storageId` 两个进程内映射；新存储再分配同工作空间默认权限。

证据：[StorageSourceService.saveStorageSource 第 405–468 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/StorageSourceService.java#L405)，重点为第 431 行旧客户端销毁、第 449 行参数写入、第 455 行初始化；[StorageSourceContext.init 第 185–206 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/context/StorageSourceContext.java#L185)。

`AbstractBaseFileService.testConnection` 只列出 `/`，成功便将 `isInitialized` 改为 true，失败包装为初始化异常；证据为 [第 112–120 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractBaseFileService.java#L112)。因此旧版测试仅证明当时能够进行相应列目录调用，不证明写入、内容读回、删除、原子不覆盖、bucket 隐私或长期可用。

**静态推论**：更新时旧客户端在新配置验证前已销毁。如果后续连接失败，SQL 事务回滚不能自动恢复静态 map 中的旧客户端。`StorageSourceContext.init` 在构建与测试之间没有关闭候选服务的 `finally`；初始化中途创建的资源可能未释放。该推论没有通过故障注入运行验证。

### 2.2 权限、根路径与请求上下文

`FileOperatorCheckAspect.uploadAround` 在获取上传 URL 和代理上传前调用权限检查；检查当前用户启用状态、用户存储授权记录、授权启用状态以及具体操作权限。证据：[第 206–228 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/aspect/FileOperatorCheckAspect.java#L206)、[allowAccess 第 358–385 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/aspect/FileOperatorCheckAspect.java#L358)。不能只因代理上传 Controller 缺少登录注解便断言上传完全没有授权。

`getCurrentUserBasePath` 优先读取分享上下文，否则用登录用户查询根路径；初始化阶段切换为管理员 ID，未配置根路径时返回 `/`。证据：[AbstractBaseFileService 第 161–179 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractBaseFileService.java#L161)。它依赖请求/ThreadLocal 上下文，在异步任务和独立服务之间不宜直接沿用。

### 3.3 上传、大小、覆盖和分片

`getUploadUrl` 构建普通 `PutObjectRequest`，签名有效期固定 30 分钟；其 `size` 入参没有加入请求约束，目标 key 也没有 create-only 条件。`uploadFile` 代理单次 `putObject(RequestBody.fromInputStream(..., size))`，没有 multipart 会话。证据：[第 409–437 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractS3BaseFileService.java#L409)、[第 567–580 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractS3BaseFileService.java#L567)。

前端 `s3FileUpload` 从返回 URL 中剥离附加的 `Content-Type` 参数，作为请求 header，整文件 `axios.put`；取消操作取消浏览器请求，未建立 provider multipart abort 状态机。证据：[useFileUpload.js 第 729–770 行](../../zfile-vue-main/src/composables/file/useFileUpload.js#L729)。`aws-chunked` 只涉及传输编码，不能当成断点续传或业务分片已完成的证据。

旧代理上传限制为 512MB，见 [application-default.properties 第 50–51 行](../../zfile-main/src/main/resources/application-default.properties#L50)。独立工程必须在应用层实际读取字节数、上传会话和 Gateway 请求限制上落实 **50 MiB = 52,428,800 字节**，不可依赖客户端报出的 size 或旧配置。

### 3.4 下载 URL 与路径契约

`getDownloadUrl` 在启用代理且未配 domain 时返回代理 URL；非私有且存在 domain 时直接拼公开 URL；其余生成有有效期的 GET 签名。配置 domain 时还修改已签 URL 的 host/path，通用 S3 会去掉路径中的 bucket。证据：[AbstractS3BaseFileService 第 130–176 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractS3BaseFileService.java#L130)。自定义域名、签名 host 与路径的正确性需要逐 provider 验证，不能由“接口兼容 S3”推得。

CRUD、list、getItem、upload 由适配器增加用户根路径；`getDownloadUrl` 和 `downloadToStream` 的入参已经含用户根或分享根，后者只再增加 storage basePath。证据：[AbstractProxyTransferService 第 203–218 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractProxyTransferService.java#L203)、[S3 downloadToStream 第 597–599 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractS3BaseFileService.java#L597)。独立实现应统一成一种路径类型，并由显式 workspace/actor 上下文一次生成物理 namespace。

代理下载公开模式会生成永久签名、私有模式生成过期签名，见 [AbstractProxyTransferService 第 104–139 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractProxyTransferService.java#L104)。签名 URL 具有 bearer 访问语义；它不能自动满足“每次请求都验证当前账号/工作空间权限”的新要求。独立首版应优先经 Gateway 鉴权代理下载。

### 4.2 SFTP

[SftpParam 第 16–45 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/model/param/SftpParam.java#L16) 配 host/port、编码、用户名/密码、私钥/passphrase、basePath 和最大连接数（默认 8）。[SftpServiceImpl.init 第 77–93 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/impl/SftpServiceImpl.java#L77) 建池，借出前验证，最大等待 15 秒。每次业务调用在 finally 中归还连接；工厂以 `pwd` 验活并关闭失效连接，见 [SFtpClientFactory 第 194–223 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/support/sftp/SFtpClientFactory.java#L194)。

列表全量调用 `lsEntries`（[第 127–147 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/impl/SftpServiceImpl.java#L127)）；创建目录用 mkdir，文件/目录删除用 delFile/delDir；复制不支持（第 293、310 行）；移动/重命名用远端 rename（[第 328–342 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/impl/SftpServiceImpl.java#L328)）；上传调用 `sftp.upload`（[第 518–531 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/impl/SftpServiceImpl.java#L518)）；服务销毁关闭池（第 591–594 行）。未见显式 create-only、符号链接限制及真实路径根边界检查。

必须避免复用的配置为 [SFtpClientFactory 第 93–95 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/support/sftp/SFtpClientFactory.java#L93)：全局设置 `StrictHostKeyChecking=no`。独立 SFTP 应校验已批准的主机指纹/known_hosts，禁止接受任意 host key；路径授权还要考虑远端符号链接和真实路径。

| 路径边界 | [StringUtils.concat 第 293–308 行](../../zfile-main/src/main/java/im/tlgxy/cloud/core/util/StringUtils.java#L293) 仅拼接和消重斜杠；远端适配器未用它实现 `..` 规范化和根检查 | 统一路径类型；拒绝穿越、编码分隔符、反斜杠、NUL 和业务名字中的路径片段；按段验证 namespace，禁止兄弟前缀误匹配 |
| 异常语义 | S3 只特判 NoSuchKey，WebDAV 特判 404，SFTP 与其他错误多为透传包装；[GlobalExceptionHandler 第 601–607 行](../../zfile-main/src/main/java/im/tlgxy/cloud/core/exception/GlobalExceptionHandler.java#L601) 对具体异常直接返回 message | 统一缺失、冲突、权限、超时、限流、远端不可用和不支持；用户响应不含原始密钥、带签名 URL、完整 endpoint 查询串 |
| 超时与生命周期 | S3 传输 override 为 30 天（[第 97 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractS3BaseFileService.java#L97)）；正常 destroy 关闭客户端与签名器（[第 701–710 行](../../zfile-main/src/main/java/im/tlgxy/cloud/module/storage/service/base/AbstractS3BaseFileService.java#L701)），失败构建路径没有等价保障 | 设置有界连接/读取/总耗时和并发预算；候选 always-close，活动替换考虑在途请求，避免关闭正在使用的实例 |

出站策略应覆盖 URL scheme/userinfo/fragment、主机/端口批准列表、解析后的 IPv4/IPv6 地址、DNS 重绑定和重定向目标。默认阻止 loopback、链路本地、云元数据等目标；确需 OSS 内网 endpoint 时由管理员配置受控例外，不能把“允许内网”变成任意私网访问许可。本段为建议，未对现有部署进行攻击或扫描。

## 6. 独立三服务接入设计

独立系统继续采用 Gateway + 账号与平台、文件与课程、智能助手三个业务服务。远程存储连接器归属文件与课程服务，不新增第四业务服务，也不从旧工程调用服务实现。

| 所属 | 建议职责 | 需要保持的边界 |
| --- | --- | --- |
| `cloud-gateway` | 路由、边缘请求大小/超时限制、可信请求上下文 | Gateway 成功不能替代业务服务的账号、workspace、mount 和路径授权 |
| `cloud-platform-service` / 账号端口 | 身份、会话有效性、工作空间成员与管理员信息 | 身份服务不可用时明确失败，不返回默认允许 |
| `cloud-drive` | 远端存储端口、规范路径、条目、游标、能力和失败类型 | 类型由独立工程定义，不继承旧 BaseFileService 或把 SDK 类型暴露给领域层 |
| `cloud-drive-application` | mount/config 状态、配额、上传/删除流程、权限复核、目录/catalog 一致性 | 远程 I/O 不持长 SQL 锁；数据库提交与远端成功之间使用可恢复业务状态 |
| `cloud-content-service` | 原生 OSS/S3 适配器、客户端生命周期、秘密解析、受控测试与 HTTP 入口 | 凭据仅服务端可见；只操作已经授权并解析好的 namespace |
| `cloud-intelligence-service` | 通过既有业务边界消费经授权的资料 | 不持有存储凭据，不绕过文件权限直接访问任意 object key |

端口可表达 `listPage`、`stat`、`createOnly`、`openRead`、`delete`、`createDirectory` 与可选 move/copy 能力；这里是接口职责建议，不宣称仓库已有这些具体方法。list 应返回有界页和与 mount、配置版本、路径绑定的 continuation cursor，不能后台遍历全 bucket 后分页。

### 6.1 provider 选择与原子不覆盖

| 优先级 | 建议适配器 | 实施约束 |
| --- | --- | --- |
| P0 | `AliyunOssAdapter`，使用阿里云原生 Java SDK | 自己处理 OSS 原生 region、认证、错误码和不覆盖能力；不移植自写 HmacSHA1 signer。核实 bucket 版本状态与配置权限后才允许写入 |
| P0 | `S3Adapter`，使用 AWS SDK v2 | 明确 endpoint/region/path-style；每个兼容厂商和配置版本单独验证条件写入、分页和 checksum 行为，不凭 S3 标签默认兼容 |
| P1 | `WebDavAdapter` | HTTPS、认证域/重定向限制、明确读超时；原子条件创建和 MOVE 行为通过协议契约测试后开放 |
| P2 | `SftpAdapter` | host key pinning、池与超时预算、符号链接/真实路径限制；不覆盖和 rename 语义验证后开放 |

官方阿里云 [Java SDK 3.18.5 发布页](https://github.com/aliyun/aliyun-oss-java-sdk/releases/tag/3.18.5) 可作为保守原生 SDK 基线候选，最终依赖需在实施时锁定并进行 Java 21 兼容检查。2026-10-27 读取的 [V2 官方 releases](https://github.com/aliyun/alibabacloud-oss-java-sdk-v2/releases) 已列出 0.6.1，不能再把 0.5.1 写成最新版本；本次读取的 README 未证明 SDK 的 preview 稳定性状态，因此不以 GitHub 文件页的“Preview”界面标签作为 SDK 预览版证据。V2 可另行评估，不在这份分析中承诺已经验证其依赖兼容性。

不覆盖必须由实际服务端能力或经过验证的等价发布机制保证：

- 阿里云官方 [PutObject 文档](https://www.alibabacloud.com/help/en/oss/developer-reference/putobject)（标注更新 2026-08-13）说明 `x-oss-forbid-overwrite=true` 的限制：在版本状态 **Enabled 或 Suspended** 的 bucket 中该 header 无效，同名对象仍可能被覆盖。因此不能承诺任意 OSS bucket 配置均满足原子不覆盖；应拒绝不满足策略的写入配置，或另行完成独立逻辑目录与不可变物理对象的发布设计。
- AWS 官方 [PutObject 文档](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html) 说明 `If-None-Match: *` 可条件创建，同名返回 412，冲突可能返回 409；文档还列出适用性限制。S3 兼容厂商必须用受控 namespace 的真实探针确认其没有忽略该条件，不能将 AWS 文档当成兼容厂商的运行证据。
- “先 HEAD，确认不存在，再 PUT”存在并发竞争，不能作为原子不覆盖实现。远端真实能力未知或不支持时，应保留未验证/不支持状态并明确拒绝写入。
- 文件移动涉及 copy + delete 时，必须分别记录目标发布和源删除结果；不得把 boolean false 丢弃后返回成功。目录递归操作未实现时保持能力关闭。

### 6.2 保存、验证、启用与能力标签

建议将配置持久化状态、验证结果和运行开关分别记录，不把单一布尔 `enable` 解释成所有能力都通过。

| 展示状态 | 精确定义 | 可以开放的行为 |
| --- | --- | --- |
| 已保存 / 未验证 | 配置格式和权限通过并持久化，未完成远程验证；可能尚无执行适配器 | 管理详情；不可假称远程文件可读写 |
| 验证中 | 指定配置版本正由临时候选客户端验证 | 有界状态查询、取消；不影响旧活动配置 |
| 读取已验证 | 指定 namespace 的列举/元信息/受控读取检查通过 | 仅当已启用且业务授权通过时开放已验证读取能力 |
| 写入已验证 | 对同一配置版本完成写探针、读回、不覆盖检查和删除清理，且策略条件满足 | 按 capability 开放 create-only 等通过的操作 |
| 验证失败 | 验证失败并记录脱敏错误及时间 | 修订/重试；保留旧活动版本 |
| 清理待处理 | 探针或业务临时对象未能删除，已登记精确资源标识 | 告知管理员，使用受控补偿流程；不能显示全部测试通过 |
| 已启用 / 已停用 | 管理员对一个可用配置版本设置的运行开关 | 每次请求还须检查当前状态、账号、workspace 与具体操作权限 |

验证结果应带配置版本、凭据版本、endpoint/bucket/namespace 摘要、测试时间与 capability 列表。保存新版本后旧验证结果不自动沿用；即便已验证，也不能代表永久健康。配置替换先建立候选，成功并提交后再切换活动引用；候选失败总是关闭，旧活动实例保持可用，在途请求结束后再回收旧实例。

### 6.3 受控连接测试与 namespace 探针

默认只读测试检查 endpoint 策略、认证、目标 bucket/mount namespace 的元信息或有界列表；该动作不请求列出账号全部 buckets、不改 bucket CORS/ACL。写验证必须由对应管理测试动作明确触发，复用管理员与 workspace 授权。

写探针流程建议为：

1. 在服务器生成的受控 namespace 内生成随机探针名，例如 `{workspaceNamespace}/__probe/{probeId}`；不允许请求直接传任意远端 key，不触及其他用户目录或 bucket 根的任意资源。
2. 持久化探针 ID、配置版本、精确 key、期限和预期字节摘要。小固定内容也计入受控测试预算。
3. 原子 create-only 创建，读取并校验实际字节/摘要；再次用同名但不同内容条件写入，预期拒绝，并确认原内容未改变。
4. 在 finally 删除本次探针的精确 key，必要时带已记录的版本/所有权条件；绝不执行按用户输入前缀递归清理。
5. 删除失败登记 `cleanupPending` 并返回清理失败事实；后台补偿仅处理自己登记的资源，重试有界且可审计。测试失败与清理失败分别呈现。

上述是未来验收设计，本次未在任何真实 OSS/S3/WebDAV/SFTP 服务执行。若 provider 不具备安全的同名拒绝语义，测试不得使已有业务对象承担验证风险。

### 6.4 鉴权、配额和私有 namespace

每次上传、下载、列表、删除与探针都需验证当前会话、有效账号、工作空间成员关系、mount 归属、启用状态和操作权限；跨 workspace、停用账号、撤销会话和失效 mount 均拒绝。物理 key 从服务器可信 workspace/mount 标识和规范相对路径推导，显示文件名不直接决定任意物理 namespace。

单文件上限为 50 MiB，必须同时限制声明长度和实际读取量。上传预留配额和唯一逻辑路径占位，读取流和远端 I/O 不持数据库长锁；发布前再次授权。远端成功后业务提交失败，应登记待确认或待清理对象，不能直接释放预算并丢弃对象；失败/取消/超时采用可恢复状态推进并释放对应预留。并发同名写入只允许一个发布成功。

下载首版经 Gateway 和 content 鉴权代理，禁用匿名公开 domain 和永久签名。将来如允许短时 provider 签名 URL，产品需要准确表达其到期前的 bearer 访问窗口、权限撤销边界与泄漏风险，并完成 URL/日志脱敏，不能继续显示“每次下载都重新验证账号”的承诺。

## 7. 设计验收矩阵

以下均为**待实施/待执行**的验收项，不是本次运行结果。本次仅完成源码阅读与官方协议资料核对。

| 类别 | 关键案例 | 预期结果 |
| --- | --- | --- |
| 账号与 workspace | 未登录、停用、过期/撤销会话、非成员、跨空间 mount ID/key、角色不足 | 业务层拒绝；不发送远端请求，不泄漏其他空间的条目或统计 |
| 保存与标签 | 仅保存配置、适配器未接线、验证失败、凭据轮换、旧验证结果遇到配置新版本 | 准确显示保存/验证/启用状态；不返回虚假连接成功，不沿用失效能力标签 |
| endpoint | HTTP、userinfo、非法端口、localhost、IPv4/IPv6 loopback、链路本地、元数据地址、DNS 重绑定、跨域重定向、已批准 OSS 内网 endpoint | 策略拒绝或按明确批准例外处理；认证信息不发送给未批准目标 |
| 路径 | `..`、双重编码、编码斜杠、反斜杠、NUL、前缀兄弟目录、Unicode、同名文件/目录、SFTP symlink | 规范化规则一致；始终留在授权 namespace；危险路径在远端调用前失败 |
| 原生 OSS 不覆盖 | 未开启版本 bucket、Enabled bucket、Suspended bucket、重复对象、并发同名创建 | 只有验证满足策略的配置可写；不把无效 header 误标为通过；已有内容不变 |
| S3 条件写 | AWS 支持范围、兼容服务正确实现/忽略/拒绝 If-None-Match、并发 412/409 | 能力按真实服务验证；忽略条件视为失败；冲突与不可重试授权错误不混淆 |
| 50 MiB | 0、50 MiB、50 MiB+1、声明小实际大、截断、取消与慢流 | 按实际字节限制；预算和临时资源正确回收；超限无可见完成对象 |
| 配额并发 | 并发上传接近限额、重试、远端成功但 DB 提交失败、失联后结果未知 | 占位和预留不重复消费或提前释放；可恢复并保留精确补偿记录 |
| 列表 | 空目录、目录标记、超过 1000 项、非 ASCII key、分页期间变化、越界 continuation cursor | 有界页、无跨 namespace 数据；cursor 与 mount/配置/路径绑定，限制明确 |
| 探针与清理 | 创建/读取/二次写/删除分别故障、取消、进程中断、重复补偿 | 只删除本次登记资源；清理失败单独显示；不自动改 CORS/ACL |
| 下载 | 撤权/停用、Range、未授权 key、原始文件名、客户端断开 | 每请求授权；正确范围和资源关闭；不泄漏凭据、带签名 URL 或其他用户路径 |
| 生命周期 | 初始化中途异常、验证失败、配置切换、并发在途传输、客户端关闭失败 | 候选必关闭；旧活动配置可用；在途请求不被无协调关闭 |
| 失败翻译 | 404、403、凭据无效、超时、限流、服务端 5xx、不支持操作 | HTTP/业务码稳定且脱敏；缺失和不可用不混为一谈；不返回假成功 |
| WebDAV | Basic 认证域、重定向、读超时、条件 PUT、文件 MOVE 尾斜杠差异 | 未批准目标不携带认证；能力按服务器测试，失败明确 |
| SFTP | host key 错误/更换、连接池满、连接失效、真实路径逃逸、rename 冲突 | 拒绝未知 host key；等待有界；路径与不覆盖策略成立后才启用写入 |
