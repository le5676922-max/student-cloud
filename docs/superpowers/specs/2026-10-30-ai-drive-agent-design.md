# AI 智能云盘 Agent：设计提案与知识建设规范

日期：2026-10-30。状态：**设计提案，尚未实现新增 Wiki、模型工具循环及训练流水线**。

本文针对当前 `backend-independent/` 开发主线。它不是已上线功能清单，也不以同名历史后端中的代码证明独立后端具备能力。线上网站不在本次修改范围内。

## 1. 独立判断与推荐方案

目标是用户描述任务，小芽利用真实业务能力完成文件和课程资料工作，并给出可验证的结果。知识库服务于任务，不以页面数量、图谱规模或模型调用次数衡量智能程度。

比较三个方案：

| 方案 | 能解决什么 | 代价及不足 | 选择 |
| --- | --- | --- | --- |
| 完善现有 RAG 和受控 Agent | 文件操作、资料定位、任务恢复，投入最直接 | 跨资料知识仍需多次综合 | 第一阶段必须先完成 |
| 在第一种方案上增加有界、按需的 Wiki | 重复使用课程概念、资料关联、操作说明，保留原文核验 | 增加来源失效传播、权限继承、生成成本 | 推荐逐步加入 |
| 立即引入完整桌面 Wiki、独立图数据库、多个自治 Agent 和周期训练 | 功能很多 | 重复建设，部署复杂，质量与资源收益未证明 | 当前不采用 |

推荐 **Agent 为入口，RAG 核验原文，Wiki 提供长期整理，Memory 保存个人偏好，评测控制更新**。微调仅做周期资格评估，不作为默认付费定时任务。

“所有功能自动化”解释为：将适合自动化的业务提供为受权限约束的工具。不能解释为模型可以自行批准成员申请、突破课程上传审批、替用户获取密码、对外公开文件或无限使用模型预算。

## 2. 已有实现与真实缺口

| 部分 | 当前源码依据 | 已有能力 | 本提案新增部分 |
| --- | --- | --- | --- |
| 对话 | `cloud-intelligence-service/.../ai/ChatService.java` | 帮助、审核知识、个人课程片段、简洁/详细格式、完成后权限与资料复核 | 模型工具选择、服务端引用校验、任务上下文 |
| 操作识别 | `.../agent/AgentIntentRouter.java` | 有限、确定性指令路由 | 受限模型计划；含糊目标先澄清，规则保留为降级路径 |
| 操作执行 | `AgentPlanService`、`AgentWorker`、内容服务 `AgentCommandService` | 预览、确认、持久任务、幂等、取消、部分失败及未知结果状态 | 多步目标编排、明确的自动执行策略、结果核验 |
| 资料检索 | 内容服务 `LearningLibraryService` | 私人资料索引，关键词召回，源摘要及授权复核 | Wiki 联合召回、共享课程正文接入、可选 embedding 适配 |
| 审核知识 | `cloud-assistant/.../ReviewedKnowledgeService.java` | 范围、发布、版本、撤回、反馈来源限制 | 多原始资料的事实血缘和依赖失效 |
| 记忆 | `MemoryService` | 用户主动保存，最多50条、每条500字符，版本、开关、删除 | 候选提炼、相关召回、有效期、冲突处理、外发选择 |
| 调度 | `AgentScheduleService` | 周期创建预览 | 在明确范围授权内执行；不是直接打开当前调度就已自动执行 |
| 评测与训练 | 现有 JUnit、前端及业务联调 | 功能与权限测试 | 版本化 Agent 场景评测；未接入模型参数训练 |

当前个人学习索引与共享课程是不同业务概念，不能因界面都出现“课程”就混用课程 ID、成员资格或资料权限。当前关键词检索也不能宣传为已经实现向量语义搜索。

还需先堵住两个学习链路缺口：`AnswerFeedbackService.exportReviewed` 的“已解决且无课程”筛选不足以证明语料可公开或可训练；`ChatService` 自动注入最近10条记忆，不等同于相关记忆召回，也不等同于每轮私人资料外发授权。

## 3. 用户可见的完成标准

首批应以六个完整任务验收，而不是只增加按钮：

1. **上传并归档**：选择本机文件→指定有权限的目标→上传→核对大小/摘要及落盘状态→按计划归档。浏览器文件须由用户选择，Agent不能任意读取用户电脑。
2. **整理已有资料**：检索选定目录→提出分类/命名方案→在已授权范围内执行→列出成功、跳过、冲突与失败。默认不覆盖同名目标。
3. **建立课程资料库**：辨别个人课程与共享课程→检查资料访问及课程上传资格→导入→提取→建立来源索引→生成课程知识页。
4. **有依据地问答**：查找原文与 Wiki→核验来源当前仍可访问→给出简短结论、出处及覆盖不足。资料缺失、冲突或无权限时明确说明。
5. **生成复习材料**：只使用选定且获准处理的课程资料生成提纲、概念解释、例题与待核对项→保存为新的 Markdown 文件→返回真实文件入口。不能编造老师考点或伪称读完全文。
6. **反馈改进**：成员点击未解决→登记问题→管理员修订→生成改进草稿→校验与审核→更新对应范围知识→运行回归，保留撤回路径。

下载交付包括权限检查及下载入口；是否成功保存到用户设备，以浏览器下载结果为准，不能仅以服务端生成链接宣称完成。

## 4. 服务与资源边界

继续使用平台、内容、智能三个业务服务及 Gateway，不为了 Wiki 再增加常驻 Java 服务。

- 平台服务负责身份、空间成员、审批与人工客服。
- 内容服务负责原始文件、存储驱动、课程、配额、读取授权、提取及实际文件操作。
- 智能服务负责对话、工具编排、Wiki、记忆、知识反馈、任务评测及模型适配。
- Gateway 负责统一入口和已有路由策略，不执行长期模型任务。

两台2核4GB ECS 的初始建议：A放Nginx、Gateway、平台和智能服务；B放内容服务、MySQL和Redis；实际以JVM堆、数据库缓冲及容器实测内存再调整。此方案不是双副本高可用，任一关键节点故障仍可能影响服务。文件处理队列与在线聊天分开限额，后台 Wiki 首期并发1，业务优先。CPU训练和本地大模型不放入这两台业务机。

MySQL保存任务、知识版本、授权和审计事实；Redis按需缓存和协调，不能作为唯一任务账本。复用现有任务/Outbox思路，增加明确任务类型及分发，不把 Wiki 作业塞进只接受 `FILE_ORGANIZE` 的旧worker。暂不增加Kafka、图数据库、外部向量集群或多Agent常驻进程。

## 5. 工具调用与自动化策略

模型只生成符合JSON Schema的工具建议，服务端检查工具白名单、参数、身份、资源、预算和当前任务状态。业务身份由服务端提供，模型不能指定他人的账号。不给模型SQL、任意shell、服务器文件路径或任意URL抓取入口。

| 类别 | 例子 | 执行规则 |
| --- | --- | --- |
| 只读 | 查询文件、容量、课程、任务状态、来源 | 当前权限内可自动执行；私有正文外发仍受处理授权约束 |
| 可恢复写入 | 新目录、无覆盖复制/移动、归档、保存新提纲 | 用户任务目标明确，且自动策略包含操作和资源范围时可执行；否则呈现具体预览 |
| 敏感业务 | 共享范围扩大、成员审批、上传资格、配额、全站知识发布、永久删除 | 要求具有相应角色并核对具体变更；不能只因“希望自动化”而越权或静默公开 |
| 身份与凭据 | 设置密码、验证码、SMTP授权码、OSS密钥、登录token | 用户在专用表单完成；Agent不读取、记忆、回显或写入知识库 |

自动策略至少记录 `owner / allowed_operations / resource_scope / external_processing / expires_at / policy_version / budgets`，可查看、暂停和撤销。每次调用重新检查策略与业务授权；策略不是无限授权，也不能跨账号继承。

初始模型循环上限建议：每任务最多8轮工具选择、12个写步骤、限定候选文件数量；这些是待实测调整的预算，不是现有常量。重复同参数或无进展时停止并解释。重试区分网络失败、明确业务失败、部分成功和执行结果未知；未知结果先查账本，不能再次写入赌成功。

任务状态应明确区分等待文件选择、等待澄清、待确认、排队、执行、部分完成、成功、失败、结果待核查、取消。界面不显示内部思维链，显示可核对的操作步骤和真实事件。

## 6. Wiki 数据与生命周期

借鉴上游的原始来源、生成知识及结构规范三层，不改变原始文件，不将模型生成答案反复摄入为独立证据。

最少需要记录以下概念，具体表名在实施计划中落实：

| 数据 | 必需字段与约束 |
| --- | --- |
| Source | 来源ID、个人/空间/共享课程范围、归属、存储/文件标识、内容摘要、源版本、授权版本、提取覆盖、删除标记 |
| PageRevision | 页面ID、不可变修订号、类型、标题、正文、状态、来源版本集合、生成配置版本、创建与发布时间 |
| ClaimEvidence | 页面断言、原始来源版本、片段/页/段定位；没有定位的内容只能标记为待核对 |
| Link | 页面间关联及其类型，按同等权限过滤，不暴露不可访问页面的标题 |
| IngestionJob | 来源及版本、任务状态、重试、幂等键、预算、错误码；不保存凭据 |
| Publication | 当前活动版本与替代/撤回记录，发布使用版本比较，避免旧任务覆盖新结果 |

流程：选定资料范围并授权→记录源变化事件→读取前复核→本地受限提取→内容哈希去重→提取结构化事实和出处→生成候选页面→确定性校验→适用发布策略→可检索版本。

ETag不能一律当文件MD5，尤其不能对所有OSS/S3分片对象这样处理。保留独立源版本或受控内容摘要。

个人授权范围内的生成页面可按策略自动发布；跨成员共享、扩大范围以及全站知识仍走相应审核。页面继承**全部证据的访问限制**，不能自动从私人资料提炼到全站。首期不混合不同可见范围的材料生成同一页，降低复杂度。

源文件修改、删除、目录撤权、课程退出及空间停用后：先让依赖页面和缓存不可检索，再异步重建。旧版本仅按其审计权限保留，不能当正常召回降级项。不能删掉 `sources[]` 中的名字却保留由该来源贡献的正文。

冲突页同时保留两边证据、适用时间与差异；不能凭模型自报置信度或多数资料相同就覆盖另一结论。没有依据时生成知识空白项，不自动联网补齐私人课程内容。

## 7. RAG、Wiki 与 Memory 如何协作

查询先确定用户目标与当前资源范围，按权限对 Wiki、审核知识和原文进行有界召回；Wiki不是所有问题必经的额外模型调用。简单文件查询直接走业务工具，简单原文问题直接检索原文，多资料解释才使用关联页。

回答需要精确事实或 Wiki过期/冲突时回源核验；Wiki中的引用必须能映射到本轮实际可访问来源。响应返回来源ID、版本、片段、覆盖提示；服务端拒绝或降级无法映射的引用，不只依赖提示词自律。

embedding使用独立适配端口，可关闭并退回关键词检索；聊天API密钥不能证明存在embedding或微调接口。对外embedding也算资料外发，必须包含在处理授权中。

Memory分为：会话内上下文、持久任务状态、长期个人偏好。持久任务状态由任务账本负责，不存为一句“已经上传完成”。长期偏好如语言、回复长度、常用课程由用户确认或在明确开启的记忆策略内保存，带来源、版本、有效期及删除入口。

记忆只召回相关条目；“默认用课程A归档”只能作为目标建议，不能赋予课程A上传权限。账号切换、关闭记忆和删除后，缓存及本轮待返回结果均需再次复核。隐私偏好不通过“模型先读一遍再判敏感”实现。

## 8. 特别详细的知识库建设标准

详细是步骤可复现、前提清楚、失败可排查、来源可验证，不是把所有内容塞进一次回答。资料库可以详细，默认回复仍应简洁，用户再按需展开。

每个产品知识条目固定包含：

1. 知识ID、标题、类型、适用产品版本、核对日期和维护状态。
2. 适用角色，个人/空间/共享课程范围，以及明确不适用的场景。
3. 要解决的问题、典型问法、别名与检索词。
4. 前置条件：登录、成员资格、存储启用、授权、容量及必要服务配置。
5. 用户入口与逐步操作，每步说明成功后应看到什么。
6. Agent可用工具、必填参数、缺失时的澄清、执行与确认边界。
7. 正常结果、部分结果、等待审批和结果待核查的区别。
8. 常见错误、可能原因、用户可处理步骤、管理员排查步骤及何时需要人工。
9. 容量、文件格式、批量数量、预算与版本差异；不能把计划值写成已实现限制。
10. 数据影响、隐私与权限继承、如何取消、恢复或撤回。
11. 示例，包括正常、参数缺失、无权限、同名冲突和失败恢复。
12. 原始依据、代码/接口/测试定位、相关知识链接、未覆盖与待核对事项。

课程知识另外包含：原始资料清单、完整性与提取失败记录、章节映射、术语定义、前置知识、公式的条件与符号、例题步骤、易错点、概念关系、不同资料的矛盾、来源定位和复习提纲。习题答案没有出处时标记为生成草稿，不伪造教材标准答案或实际考试范围。

首批产品知识目录如下；这是建设清单，**不是声称这些新页面已经发布**：

| 主题 | 需要详细覆盖的内容 |
| --- | --- |
| 账号与身份 | 初始化、邮箱注册、账号ID、邮箱登录、旧账号兼容、会话失效、成员自行找回密码 |
| 空间加入 | 管理员入驻、邀请码加入、名称申请、待审核/拒绝、邀请码失效/人数/时间、课程邀请码区别 |
| 角色与隐私 | 全局/空间管理员/成员边界、个人目录隔离、管理员不能代设成员密码、跨空间拒绝 |
| 存储添加 | LOCAL/OSS/S3适用范围、连接字段、读写回读清理测试、本地存储审批、凭据专用输入 |
| 云盘授权 | 成员申请、普通管理员审批、目录范围、上传资格、配额计算、撤权和容量不足 |
| 文件生命周期 | 浏览、选择、上传、续传、下载、预览、重命名、复制/移动、同名冲突、回收站与恢复 |
| 分享 | 必须登录、范围与有效期、访问限制、撤回、远程源尚不支持的能力 |
| 个人学习 | 个人课程、资料引用、索引格式、正文提取、覆盖限制、资料更新、删除与失效 |
| 共享课程 | 创建者、邀请、跨空间管理员加入、成员资格、持续上传权申请、审批、撤销与资料共享 |
| Agent任务 | 目标描述、文件选择、资源绑定、计划、自动策略、进度、取消、重试、部分失败与未知结果 |
| Wiki | 资料授权、摄入、概念页、来源、冲突、增量更新、检查、撤回与重建 |
| 长期记忆 | 偏好保存、相关召回、查看/修改/删除、关闭、过期、敏感内容和任务状态区别 |
| 问答与反馈 | 简洁/详细、来源、原文核验、覆盖不足、未解决反馈、管理员整理、人工客服 |
| 运维与诊断 | 服务职责、Docker/Nginx、健康检查、日志、慢请求、数据库/Redis/SMTP/模型配置与降级 |

知识来源优先级：当前实现与接口契约、业务规则和测试、已审核说明、用户授权资料。历史需求或历史后端文档只能作为待核对线索。实现变化后更新对应条目和评测，避免知识库教用户调用已经退休的接口。

## 9. 自动评测与微调资格检查

离线评测使用合成文件和不同账号/空间/课程的隔离环境，不改真实用户数据。首批评测集建议至少80条，按来源/时间分组留出；这是目标，不是现有通过数量。

- 任务：意图、参数澄清、工具选择、完成证据、幂等、取消、重试、部分失败及未知状态。
- 知识：相关命中、引用存在、引用是否支持结论、冲突说明、资料过期、拒答与覆盖不足。
- 安全业务：跨用户/空间/课程、撤权、配额、成员审批、敏感信息、文档中的恶意操作指令。
- 表达与效率：简洁格式、无虚构成功、响应首字/完成耗时、p50/p95、token与调用成本。

权限、凭据泄漏、越权执行等确定性测试任何一项失败均阻止候选发布。LLM裁判可以辅助语义评分，不能判断谁有权限。单元测试、合成模型通过与真实模型质量评测分别记录，不相互替代。

周期先做知识过期检查、坏例分类和候选改进评估。只在证明提示词/检索/工具设计不足，且有足量经审核、有许可、去重且无泄漏的样本时，才进入微调可行性评审。没有适用供应商、费用预算、数据外发范围和独立留出集，不启动外部训练。微调目标偏向稳定的工具选择和表达，不用于记住实时权限或用户私人文件。

## 10. 实施顺序与验收门槛

1. 完成已有安全与账号隐私修复，固定权限、工具及结果状态契约；建立首批任务评测基线。
2. 增加严格工具注册、模型选择、自动策略和可恢复编排；先验收上传归档、分类整理、索引三种任务。
3. 建立详细产品知识与来源规范；补齐共享课程与私人资料的不同索引权限路径。
4. 按需增加 Wiki 来源、修订、依赖失效、摄入/检查队列及可见进度；先个人范围再共享。
5. 完善Memory相关召回、候选、有效期与外发策略；接入反馈和自动回归。
6. 用同一批资料、相同权限和资源预算比较“RAG+Agent”与“增加Wiki”；收益不足时保持Wiki关闭。
7. 评估embedding、重排及微调资格；不承诺未测得的延迟、召回率或对其他项目的全面性能优势。

每阶段均需：失败回归、当前功能不退化、真实业务接口核对、资料撤权测试、更新文档和能力清单。上线、数据迁移及付费训练不由本提案自动触发。
