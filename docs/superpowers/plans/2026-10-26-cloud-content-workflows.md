# Student Cloud 文件业务实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans task-by-task. 用户已确认采用六项业务；不重新进行框架选型。

**Goal:** 在现有独立后端落实文件元数据、可恢复上传、回收站、权限预设、登录分享和管理统计，保持原前端主题。

**Architecture:** 平台、内容、智能三个业务服务与 Gateway 不变。文件业务持久化归内容服务，平台只通过内部接口读取脱敏统计；不会跨库 JOIN。当前本地文件由单内容实例持有，上传会话绑定节点，不能把不同服务器本地盘宣称为共享盘。

**Spec:** 已确认的 Tank 业务取舍及 `docs/Spring-Cloud微服务架构与实施计划.md`。Tank 只提供业务参考，不引入它的运行代码。

## 全局约束

- 保持已有工作目录与未提交工作，延续执行账本；不修改旧 backend、不部署、不提交或推送 Git。
- 用户必须登录，读取文件、分享、恢复和上传提交均重新核验授权。
- 所有写入不覆盖已存在文件。SQL 短事务、唯一约束和版本用于跨进程协调，不以进程内锁作为唯一保障。
- 单文件继续保持现有 50MiB 内核上限；续传每块4MiB、会话24小时、每人3个活动会话及100MiB暂存预留。
- 元数据索引是有期限的目录快照；权限不从索引决定，实际下载和写入走文件内核。显式刷新及写入失效要可用。
- 删除默认回收站，7天到期；回收站仍在原个人根内占容量，原路径从浏览器隐藏。恢复不覆盖同名文件。
- 分享只支持有界单文件、明确选择本空间登录成员或课程成员；默认7天、最多30天；不接入匿名提取码或第三方Office。

## 任务与验收

### 1. 元数据目录与回收站（root）

Files: `cloud-drive-application/.../FileCatalog.java`, `MountService.java`, `cloud-drive/.../LocalFileStore.java`, `db/independent-file-catalog-schema.sql`（V8）与 `db/independent-recycle-schema.sql`（V11）, 内容HTTP与前端回收站。

- [x] 写测试：相同目录缓存不重复扫描，权限/根版本隔离，变更立即失效，分页/关键词查询；回收仍计容量、恢复冲突、不同用户隔离、异常移动不误报成功。
- [x] 目录快照存文件ID、虚拟路径、父目录、大小、修改时间与快照代次，短TTL；列目录先验证真实目录与权限。写入失效同挂载快照。
- [x] 内核提供系统私有回收操作，遍历/下载拒绝系统前缀；回收记录绑定真实授权根，异常保留UNCERTAIN，不自动重复文件副作用。
- [x] 接通列表/恢复/彻底删除/到期清理界面及API，普通删除显示去回收站。

### 2. 续传与上传任务（resumable_uploads）

- [x] 先测所有权、配额、块长度/摘要、重复块、取消/过期、完成幂等和目标冲突。

### 3. 登录分享（controlled_sharing）
