# 业务响应优化说明

更新：2026-09-25。范围：当前工作区的业务与功能优化，非上线公告。适用于单后端实例，不新增 Redis，不重建业务数据库。

## 1. 目录按页加载

文件页每次请求一页，使用原有每次显示数量配置，前端限制为 1–200 项，未配置时 100 项。翻页替换上一页数据，不在内存中无限追加；列表、卡片和图库均有分页入口。批量选择、图片画廊、音视频连续播放只作用于当前页。

文件名过滤作用于当前目录全部可见条目，忽略大小写，不递归子目录。每次翻页仍重新检查身份、存储授权、用户根目录和隐藏／禁止访问规则，再排序和分页。游标绑定当前授权结果、排序、查询及页面大小，不是访问凭证。目录变化导致游标失效时提示并重新读取第一页，避免混用不同目录快照。

`POST /api/storage/files` 可选参数：

| 参数 | 含义 |
| --- | --- |
| `pageSize` | 1–500，文件页进一步限制为最多 200 |
| `pageCursor` | 上次响应的 `nextCursor` 或 `previousCursor`，调用方不要自行拼接 |
| `nameQuery` | 最多 200 字符的当前目录文件名过滤 |

分页响应包含 `paged`、`files`、`total`、`offset`、`pageSize`、`nextCursor` 和 `previousCursor`。不传 `pageSize` 保留旧调用方式；文件选择器和分享接口没有强行切换分页。

**性能边界：**现有存储驱动仍在每次请求枚举并排序整个目录，然后截取响应；没有改造所有云存储的原生分页，也不是虚拟滚动。这轮主要减少网络负载、前端常驻数据和 DOM 数量，不承诺改善驱动扫描耗时。合成 10,000 项、每页 200 项的序列化样本从 1,189,030 字节降至 23,694 字节，约减少 98%；不包含 HTTP 压缩和浏览器渲染耗时。

## 2. PDF 单页预览

一次只渲染当前页，支持上一页、下一页、输入页码、50%–200% 缩放和适合宽度。焦点位于阅读器时支持左右键翻页、加减键缩放，不占用正文输入框的按键。保留文字选择和链接标注层；加载失败可重试，加密 PDF 可输入密码。

切换文件、重试和关闭预览会释放旧加载器；旧文档的异步回调不能覆盖新文档。画布宽度上限 2,400 px，用组件宽度统一缩放文字和注释层。

按页渲染不意味着只下载一页数据，实际下载行为仍由 PDF 服务的 Range 支持和 PDF.js 决定；它也不会为课程资料提取增加 OCR。

## 3. AI 真流式回答与停止生成

小芽通过带登录请求头的 POST 请求读取 SSE，展示上游真正返回的文字片段以及检索／工具阶段，不是把最终答案重新做打字动画。停止生成会同时取消浏览器请求，并请求服务器关闭本账号对应的上游连接。不能取消其他账号的对话，令牌不放入 URL。

生成中文字尚未完成，不能据此认定文件已经修改或答案有依据。最终回答、知识依据、课程片段和任务卡片均使用服务端完成结果替换；中断内容不进入下一轮对话历史。模型工具仍不能确认执行任务。

配置前缀：`tongligong-student-cloud.ai`。

| 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| `chat-timeout-seconds` | 90 | 一轮生成／工具阶段的总预算，可配置 10–180 秒 |
| `timeout-seconds` | 45 | 单次模型 HTTP 请求超时，沿用已有配置 |
| `max-concurrent-chats` | 8 | 单实例同时处理的对话数，可配置 1–32 |

每账号同时最多 2 轮；超额立即提示繁忙，不使用无界队列。整轮预算不包含上传及附件预解析；本地解析或文件 I/O 不是所有步骤都可硬中断，后续阶段会重新检查取消／超时状态。流式连接结束但未收到完成事件，按失败处理，不伪造成功结果。模型服务不支持流式协议时明确报错，不自动额外发起计费请求。

接口新增：`POST /api/ai/chat/stream/{UUID}`、`POST /api/ai/chat/files/stream/{UUID}`、`POST /api/ai/chat/cancel/{UUID}`；旧 JSON 接口保留。前端需现代浏览器的 Fetch Stream 与 AbortController 支持。

### Ubuntu / Nginx 代理

将下列设置合并到现有 AI 代理 location，保留项目原有的认证、转发头和 TLS 设置。不要创建第二个冲突的相同 location。

```nginx
location /api/ai/chat/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    gzip off;
    proxy_read_timeout 210s;
}
```

8080 按实际后端端口替换；应用同时返回 `X-Accel-Buffering: no`。其他网关、CDN 也不能缓存或缓冲该流。未在你的 Ubuntu 服务器或真实外部模型上验证这段配置；上线前用非敏感问题检查首段输出是否提前到达。

## 4. 有界后台任务与课程解析

文件整理、批量归档仍先预览、再由用户确认；确认后交给 2 个工作线程和最多 16 项队列，不再让一个 HTTP 请求等待整批完成。队列满时保留待确认状态；重复确认通过数据库条件更新防止同一任务重复执行。页面约每 1.5 秒读取状态，终态停止轮询；连续网络失败会退避，随后提示手动刷新。离开页面会停止轮询，不停止后台任务。

每一步重新检查账号是否启用、当前文件权限和路径身份。后台只携带服务器确认的用户 ID，不复制请求或登录会话；线程结束后清理身份，防止下一个任务串号。每步保存结果，失败后不执行后续步骤，已成功的文件操作不回滚。

重启将遗留运行记录标记为 `INTERRUPTED`；文件写入与数据库检查点不是原子事务，绝不自动重试未知完成步骤。用户应核实实际文件和索引，再创建新预览。此版本仅支持单实例，启动第二实例可能错误中断第一实例的运行记录。

课程 PDF/DOCX 解析不再持有全局锁或长数据库事务；最多同时解析 4 份文件，容量已满时提示重试。同一用户的最终写入使用短锁，覆盖事务实际提交，重复资料和容量限制在写入前再次检查。不同用户不再因某一份慢文档共用同一把解析锁。提交前仍重新检查授权和完整文件指纹。

## 5. Redis 与部署边界

这轮没有启用 Redis。先解决多余传输、全部页面渲染和同步等待，不把本地缓存简单替换为网络访问。后续需要多个实例时，应一起设计权限缓存失效、分布式限流、任务领取租约／心跳与故障恢复；仅配置 Redis 地址不足以实现多实例安全。

沿用 Flyway V62 任务表，无额外 V63 迁移。测试使用临时数据库和合成文件，不代表生产库已经升级。真实外部模型、MySQL 本轮实测、浏览器点击验收和服务器并发压测的完成情况以 [项目测试报告](../项目测试报告.md) 最新日期为准。
