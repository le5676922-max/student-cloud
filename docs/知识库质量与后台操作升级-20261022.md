# 知识库质量与后台操作升级（2026-10-22）

## 这次的“训练”指什么

本轮改进的是 RAG 的知识内容与检索质量，不是微调聊天模型，也没有更换模型权重。没有把云盘所有文件自动收集为全站知识，没有调用付费训练或嵌入接口。

知识分为两个独立范围：

- 项目使用帮助：随代码维护的管理员／用户 JSON，校准到当前功能后重新生成运行资源。
- 私人课程资料：登录账号在 `/learning` 主动选择的资料，继续按账号隔离、实时复核权限与完整文件指纹。

长期记忆仅用于个人偏好和背景，不替代项目帮助或课程证据。

## 改进的检索行为

课程关键词召回现在区分文件名、标签与真正的正文命中。正文相关片段优先，罕见关键词与短语得到更明确的权重；文件名或标签单独命中只提供一个开头候选，不再把整份文件的无关片段都算作命中。

多份资料命中时先展示不同文件的相关片段，空位才补充同一文件的其他片段。同一路径被登记在多门课程时，也不会仅因索引 ID 不同而挤占不同文件的优先位置。这是一项有界的多样性策略，不是语义理解或事实正确性的保证。

只有文件名或标签命中、没有正文或有效语义依据的开头候选，放在真正的正文／语义证据之后补位，避免“增加来源数量”反而挤掉有效摘录。语义服务失败时不保留虚假的语义来源标记。

原有每段 700 字符、步长 600 字符的边界及 `M编号-S片段号` 引用保持不变，不需要因为此次排序改动清空旧索引。匹配时兼容大小写、全角英文，仍返回原始摘录。常见提问套话不计入有效课程关键词。

最终仍至多返回 5 个通过当前访问权限和完整 SHA-256 校验的片段。权限撤销、内容变化或文件不可读时跳过，不把数据库中的旧文本直接当成当前证据。指纹只在本次请求内部复用，不跨请求缓存。

项目帮助即使把最低分调为 0，也不会返回完全没有匹配依据的随机条目。历史停用角色不能借知识库接口取得正常登录身份。检索分数只是相对排序值，不是“答案准确率”。

## 怎样真正改善你自己的课程知识

1. 进入“课程资料”，按课程和学期分组，选择有授权的本地文件建立索引。
2. 优先导入文字清晰、主题单一、版本明确的资料；文件名和标签写清课程主题，但不要把无关关键词堆入标签。
3. 每份资料查看覆盖信息。目前常规课程提取上限为 240000 字符、PDF 前 300 页，单文件仍不超过 5 MiB；有上限不等于所有文件一定覆盖到上限。
4. 扫描 PDF 需要管理员明确启用并安装可用的 Tesseract。仅在普通 PDF 提取为空时尝试 OCR；混合 PDF 中的图片不会自动逐页补识别。默认 OCR 还有独立页数、时间和字符预算。
5. 编辑原文件后主动“重新索引”。文件移动或重命名后的旧路径若未同步成功，使用“重新关联”选择新的授权文件并索引；不要重复执行已经成功的文件移动。
6. 准备你熟悉答案的 10–20 道真实问题，核对召回的文件、摘录和覆盖范围；没有依据时补充资料或换具体关键词，不应强迫模型编出答案。

可选 embedding 仍需要单独的兼容服务配置。没有兼容索引、配置关闭或服务不可用时，保留关键词检索。搜索不会顺便重建所有向量或把全文重新上传；主动建立或刷新语义索引时，相关私有文本才可能发往所配置的外部服务，应先确认授权。聊天模型能用不等于已配置嵌入模型。

## 管理员操作

存储源管理增加本地状态筛选、数量提示和清晰的空状态。筛选只处理已读取列表，不为每次切换请求数据库。启用状态和令牌异常仅代表已有配置／令牌响应，不能证明存储服务实时可用。

搜索或筛选期间暂停拖动排序，避免把可见子集错误保存为全部顺序。清空筛选后恢复全量排序；刷新失败保留的旧数据会标明不是本次刷新结果。常用操作提供真实按钮和键盘入口，删除保留在更多菜单中。

这次不修改用户权限、角色归属、数据库结构、登录界面或既有文件读写协议。

## 验证与边界

新增离线合成课程样例，检查关键词与正文位置、文件名误命中、不同文件优先、全角匹配、无关问题、权限撤销、旧指纹和引用边界；同时校验项目帮助源文件与运行资源一致。

这些测试验证固定样例上的检索行为，不是对真实课程、真实模型答案质量或生产并发容量的全面评测。真实 OCR、外部 embedding 和模型回答效果仍需使用经过授权的代表性资料单独验收。

项目帮助更新后需重建并重启后端；仅编辑 JSON 源文件不会改变已运行的 Java 进程。前端开发环境通过热更新加载管理页面改动。未自动提交或推送 GitHub。

### 本轮实际结果

- 项目帮助：用户 67 → 77 条，管理员 98 → 113 条，原有条目 ID 保留，源 JSON 与运行资源一致。
- 固定项目问句回归：29 个问题的预期来源都出现在各自角色的前 4 条中；另有空查询、无关问题、受众隔离和知识事实测试。这是固定测试集的来源召回结果，不是大模型回答准确率。
- 课程合成样例：数据库、数据结构、网络、机器学习、操作系统等 6 个提问的首个来源符合预期；整个质量测试类共 16 项通过，含元数据泛滥、语义来源分类、Unicode、实时权限与指纹回归。
- 最终 `mvn test`：851 项，834 通过、17 跳过、0 失败／错误。跳过项仍为需明确启用的真实 Redis、真实模型、磁盘基准及部分 Windows 符号链接场景，不算验收通过。本轮 HTTP 回归使用隔离测试库，没有在业务库创建测试账号。
- 打包前知识库／学习安全定向回归：100 项，99 通过、1 个磁盘基准跳过；`package` 成功。首次打包曾因运行中的 JAR 被占用而失败，已停止已核实的本机后端后重打包并恢复服务。
- 前端：560 项全部通过，类型检查、修改文件的 ESLint、生产构建通过。构建仍有既有预览模块超过 500 kB 的分块提醒；未把这次 UI 改动当成预览体积优化，也未进行浏览器逐页视觉验收。
- 本机新版已启动：前端 `http://127.0.0.1:5178/`，后端 `127.0.0.1:8080`。后端启动日志确认加载上述 190 条帮助，原 MySQL `student_cloud` 仍为 V73，无新迁移；安装状态接口业务码 `0`、`installed=true`，匿名知识库请求返回 HTTP 401。该健康检查不等于对生产 MySQL、邮件、对象存储和付费模型做了完整压测。

本地后端重启可能使原有内存会话失效，遇到登录过期请重新登录。原业务数据、私人课程索引和长期记忆没有为本轮优化而清空。
