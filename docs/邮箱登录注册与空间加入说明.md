# 邮箱登录、注册与工作空间加入

## 一、访问与身份规则

本地登录入口：`http://127.0.0.1:5173/login`，前端代理后端 `http://127.0.0.1:8080`。

- 登录框同时支持已验证邮箱、系统账号 ID 和原有用户名，密码不去除首尾空格。
- 新注册账号由系统分配，例如 `SC` 开头的 16 位十六进制账号；每个账号独立且不可修改。不要把它与数据库内部数字主键混淆。
- 老账号补充了稳定账号 ID，用户名、密码及文件授权均保留；未绑定邮箱的老账号继续使用账号 ID 或原用户名登录。
- 注册成功后展示账号 ID，可复制保存；注册不会自动登录。

| 身份/加入方式 | 注册结果 | 后续操作 |
| --- | --- | --- |
| 普通管理员（空间管理员） | 邮箱验证后创建新的独立工作空间，无需审核 | 注册成功即可使用邮箱或账号 ID 登录 |
| 成员 + 有效邀请码 | 直接成为该空间的成员 | 使用邮箱或账号 ID 登录 |
| 成员 + 工作空间名称 | 创建待审核账号，没有文件授权 | 等待该空间管理员批准后登录 |
| 全局管理员 | 不支持公开注册 | 保留原有系统管理员账号 |

普通管理员即空间管理员，邮箱验证后创建并管理自己的新空间，无需审核，注册成功即可登录。普通管理员不能通过注册接管已有空间，也不能进入全局管理员后台。当前版本会为新建空间自动开通“空间共享云盘”，按不可变空间 ID 隔离本地目录并授予空间管理员使用权限；这不是每个成员独立的私人目录，也不是容量配额。新建空间不会获得其他空间的存储源。自动开通需要后端对 `STUDENT_CLOUD_WORKSPACE_STORAGE_ROOT` 指向的私有持久化根目录有写权限，且该目录必须与续传暂存目录分离；历史空间可由全局管理员显式开通，已撤销的权限不会因重复开通而恢复。

## 二、注册步骤

1. 在登录页选择“注册账号”，填写自己的邮箱，点击“发送验证码”。
2. 从邮箱中取出六位验证码，填写密码及确认密码（8～128 个字符），昵称可选。
3. 创建工作空间：选择空间管理员，填写一个未被使用的空间名称。
4. 加入工作空间：选择成员，再选择邀请码或空间名称。空间名称必须准确，且需要管理员审核。
5. 注册成功后保存账号 ID，选择“返回登录”，使用邮箱或账号 ID 和密码登录。

验证码有效期 10 分钟，同一邮箱 60 秒内不能重复发送，最多尝试 5 次，只能使用一次。已消费的验证码即使后续空间校验失败也不能再次使用；请检查信息并重新发送验证码。

当前版本已提供邮箱找回密码：在登录页选择“忘记密码”，使用绑定邮箱接收专用验证码并设置 8～128 位新密码。找回密码与注册验证码按用途隔离，不能混用；重置成功后原密码与旧会话失效。未绑定邮箱、停用、待审核或所属空间停用的账号，不能利用此流程绕过访问限制。为避免泄露账号是否存在，接口使用统一结果提示；收到发送提示或验证码本身不表示该邮箱一定绑定了可用账号。未配置发件服务时不可使用邮件找回密码。

## 三、管理员操作

空间管理员登录后进入“工作空间管理”：

- “邀请成员”：设置有效天数及使用次数，创建并复制邀请码。有效期 1～30 天，使用次数 1～100 次；完整邀请码只在创建时展示一次，列表不再显示。
- 可以撤销邀请码。过期、撤销、次数用完、空间停用或发起管理员停用的邀请均不能继续使用。
- “加入申请”：检查邮箱、账号 ID、昵称，再批准或拒绝。只有申请所属空间的管理员可以处理。
- 待审核或被拒绝账号不能通过普通“启用成员”按钮绕过审核，也不能登录。
- 成员只继承本空间管理员在本空间内已有的文件授权，不获得其他空间的访问权。

手动创建成员仍保留原有入口。手动用户名不能占用邮箱格式或系统 `SC` 账号格式；注册账号的系统 ID 不会因昵称/旧用户名变更而改变。

## 四、QQ 邮箱发信配置

QQ 邮箱发件服务已接入。授权码是 SMTP 使用的专用凭据，不是 QQ 登录密码；请按 [QQ 邮箱官方帮助](https://service.mail.qq.com/detail/0/75) 开启 SMTP 并管理授权码。

本地私密配置位置：

`backend/application-local-secrets.properties`

该文件已被 Git 忽略，不会打包进后端 JAR。它与 MySQL 私密配置可以共存。配置模板为 `backend/application-local-secrets.example.properties`；实际授权码不要写入前端、普通文档或 `src/main/resources`。

```properties
# 替换成你的发件邮箱和专用授权码；不要提交真实值。
tongligong-student-cloud.registration.mail.enabled=true
tongligong-student-cloud.registration.mail.host=smtp.qq.com
tongligong-student-cloud.registration.mail.port=465
tongligong-student-cloud.registration.mail.username=your-account@qq.com
tongligong-student-cloud.registration.mail.password=your-smtp-authorization-code
tongligong-student-cloud.registration.mail.from=your-account@qq.com
tongligong-student-cloud.registration.mail.auth=true
tongligong-student-cloud.registration.mail.ssl=true
tongligong-student-cloud.registration.mail.starttls=false
# 至少 32 字符的稳定随机密钥，重启时不要随机更换；当前部署仅支持单后端。
tongligong-student-cloud.registration.mail.code-secret=replace-with-your-own-random-secret-at-least-32-characters
```

修改配置后重启后端。未配置发件邮箱时，页面会明确提示并禁用发码及注册，不会返回假的验证码。邮件连接、读取、写入均设置了超时，避免邮件服务器异常时长期卡住请求；具体背景见 [Spring 邮件文档](https://docs.spring.io/spring-boot/reference/io/email.html)。

在 Docker 后端容器中，通过环境变量配置（只写示例，不包含实际凭据）：

```yaml
# 合并到你现有后端服务的 environment 节点中。
environment:
  MAIL_ENABLED: "true"
  MAIL_HOST: smtp.qq.com
  MAIL_PORT: "465"
  MAIL_USERNAME: ${MAIL_USERNAME}
  MAIL_PASSWORD: ${MAIL_PASSWORD}
  MAIL_FROM: ${MAIL_USERNAME}
  MAIL_AUTH: "true"
  MAIL_SSL: "true"
  MAIL_STARTTLS: "false"
  MAIL_CODE_SECRET: ${MAIL_CODE_SECRET}
```

服务器环境文件里放真实值，并限制读取权限；只将该文件用于容器启动，不提交 Git。授权码更换后需重新创建后端容器使新环境变量生效。生产网站还应由 Nginx 提供 HTTPS，避免账号密码在网络上传输时暴露。验证码摘要、发送冷却及错误次数存入 MySQL，基础流程不要求 Redis；生产 Compose 另外使用 Redis 提供共享限流，限流依赖异常时默认拒绝发送。保持服务器时间同步并稳定保存 `MAIL_CODE_SECRET`。当前系统的登录会话、Agent 队列及目录票据尚未完成多实例改造，**保持单后端部署**，不能仅因验证码存入 MySQL 就启动多个后端。

## 五、接口和迁移

所有接口沿用项目的 `code/msg/data` 响应格式；登录继续使用 `username` 请求字段承载邮箱、账号 ID 或旧用户名。

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| POST | `/user/login` | 登录，返回 token、role、accountId、email |
| GET | `/user/registration/config` | 查询注册和发信服务状态，不返回凭据 |
| POST | `/user/registration/email-code` | 发送注册验证码，参数 email |
| POST | `/user/register` | 注册，参数见前端表单 |
| GET | `/user/password-reset/config` | 查询找回密码服务状态 |
| POST | `/user/password-reset/email-code` | 发送找回密码验证码，参数 email |
| POST | `/user/password-reset` | 重置密码，参数 email、emailCode、password、confirmPassword |
| GET/POST | `/api/workspace-admin/invitations` | 查看邀请记录/创建邀请码 |
| DELETE | `/api/workspace-admin/invitations/{id}` | 撤销本空间邀请 |
| GET | `/api/workspace-admin/join-requests` | 查看本空间待审核申请 |
| POST | `/api/workspace-admin/join-requests/{id}/review` | 审核，参数 approve |

邮箱注册功能相关的 Flyway V65～V67 增加账号、邮箱、邀请、加入申请、验证码表及唯一约束，并扩大 MySQL 密码哈希字段长度。当前源码还包含后续版本迁移，启动时会自动执行尚未应用的脚本。不要重建业务数据库，也不要修改已经执行的迁移文件。升级已有业务库前应另行制定可恢复方案，仓库不包含用户数据库或备份。

新密码使用 PBKDF2-SHA256 加随机盐；原有哈希仍可验证。验证码只保存带密钥的摘要；完整邀请码只保存哈希。接口、列表和日志不输出密码或验证码。
