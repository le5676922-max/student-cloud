# 语义检索内存边界

本次收紧的是资料检索的数据库读取和向量索引大小，不改变前端页面，也不自动把历史资料发送给外部模型。

## 检索路径

1. 每个后端进程最多同时执行两次完整资料检索；无槽位时立即提示稍后重试，不排队占用请求线程。槽位在读取用户或资料数据库前取得，一直持有到返回片段的新鲜权限、完整文件指纹复核结束，异常也释放。
2. 第一条资料查询始终排除向量 JSON 和模型签名，仅读取本账号最多30份资料的文字及索引元信息。
3. 仅在语义功能已启用时执行第二条查询：绑定当前账号、第一条查询的资料 ID，数据库先按 `LENGTH(embedding_json) <= 1048576` 筛选，再将向量返回 JDBC。只选择 ID、向量 JSON、模型签名、实际段数；最多30份、向量正文合计不超过30MiB。
4. 第二条查询同时比对第一条查询中的课程、存储源、路径、文件指纹、索引时间，避免两次读取之间发生刷新、移动或重新关联时把新向量配给旧文字。模型签名仍须匹配当前配置。
5. 返回片段前继续重新解析当前授权、目录规则和完整文件指纹。上述数据库快照校验不是授权缓存。

30MiB是单次第二查询的向量正文上限，不是整个请求的 Java 堆内存上限；JSON解码、文字、候选排序和响应仍消耗内存。两个检索槽位是单实例内的限制，多实例不能把它视作全局容量承诺，正式部署仍需监测和压测。

## 新旧索引

新向量 JSON 不超过1MiB。建立索引前按模型维度预估预算：每个浮点数预留16个字符，另计逗号和数组括号，并保留最多64段的上限。高维模型会减少实际索引段数，页面说明显示真正覆盖的段数；余下文字仍参与关键词检索。最终序列化后再次核查1MiB上限，不将意外超大的结果写入数据库。

旧版可能存在超过1MiB的向量。它们不会随搜索读取到 JDBC，也不会由搜索自动重新嵌入；其关键词检索保留，响应说明提示索引超限或已变化、可主动重新索引。原有索引没有被批量删除。

## 回归范围

新增测试检查高维段数缩减、最终编码超限、历史超大索引的关键词回退、SQL字段/字节长度/账号边界、两次查询之间的版本和路径变化、权限撤销、指纹变化、完整检索并发以及异常释放。第二次查询测试使用内存 SQLite 执行生成的真实过滤 SQL，不使用真实用户数据库或外部嵌入 API。

测试文件：`LearningSemanticIndexTest`、`LearningSemanticSearchBudgetTest`。执行结果以最后统一运行的后端测试报告为准；编写此说明时没有另行运行 Maven。
