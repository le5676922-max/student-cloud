# A 侧独立增量交付记录

本轮基于用户指定的桌面 `student-cloud-main`，完成 A01 的 LOCAL 大文件独立增量，以及 A06 的隐私导出、记忆版本保护和对应产品帮助更新。B 正在开发，尚未提供共同合同；本记录不把暂存准入视为 B01 容量账本，也不宣称 B02 操作收据、版本中心、OCR 或 Agent 新工具已上线。

## 已交付的行为

### A01：LOCAL 大文件

- 以前独立前端与后端都固定50 MiB；现在 LOCAL 通过服务端能力动态协商，最高1 GiB，分片仍4 MiB，严格校验最多256块、块摘要和 manifest。
- 普通 multipart 与远程读写保留50 MiB；文件预览、课程解析、转换预算没有随传输扩大。大文件续传未配置时明确拒绝普通上传回退。
- 文件仍流式合并、暂存、发布和下载，保留授权代次、最终用量检查、mount/grant 锁与硬链接不覆盖发布。移动、回收、恢复等 LOCAL 内核可处理已接收的大文件，仍有有界树扫描限制。
- 按现有四份副本峰值预留暂存；全局 SQL 准入锁内同时核对已接受但尚未落盘的承诺。分别检查 staging、系统 tmp 和实际目标父目录所在卷，不把不同盘符的空闲量相加。
- 旧会话原先只记一份大小，新准入按四份折算其未释放承诺，无需修改已应用的迁移。
- 完整256块及assembled文件可清理。过期 `COMPLETING` 保留记录和预算，相同文件重新 init 返回原任务，不重做发布；OPEN仍按24小时过期。
- 浏览器没有流式保存能力时，大于50 MiB会在GET前停止并提示；失败不自动重新GET或退回整文件Blob。账号、目录、下载权限或预算变化会取消下载。
- 流式下载采用大小相关的有界总时限：`max(120秒, ceil(size/MiB)+60秒)`，硬顶1200秒；1 GiB为1084秒。小文件Blob仍120秒。

配置位于内容服务，当前 Compose 模板亦已接线：

| 环境变量 | 默认字节 | 意义 |
|---|---:|---|
| `SC_LOCAL_MAX_FILE_BYTES` | 1073741824 | LOCAL 单文件上限，硬顶1 GiB |
| `SC_UPLOAD_ACTOR_STAGING_BYTES` | 4294967296 | 个人未释放峰值暂存预算 |
| `SC_UPLOAD_GLOBAL_STAGING_BYTES` | 8589934592 | 全站未释放峰值暂存预算 |

暂存根、课程根、托管根仍必须独立且存在。预算是准入阈值，不会预先创建8 GiB占位文件；外部程序写满磁盘仍可能导致失败。当前跨卷检查刻意偏保守，宁可拒绝新任务也不重复承诺已有任务空间。

### A06：个人控制与隐私

- 管理员导出通用问答时，复用发布来源核验。私人资料、本人记忆、附件、私有会话、课程、缺失来源不导出；人工修订不能消除来源限制。其他核验异常不被吞成公开内容。
- 最多检查最近500个已整理候选，输出只含问题与修订答案，过滤后可能少于500条。前端已说明此范围。
- 记忆更新/单项删除必须提交页面实际读到的 `expectedVersion`，服务端不替客户端选最新版本。正文 A→B→A、旧窗口更新/删除均触发冲突；草稿保留供核对。
- 产品帮助目录修订为 `2026-11-01-a-independent-v1`，补齐大文件、续传、浏览器保存、版本冲突与导出来源说明。42条目录及角色过滤机制保持。

**兼容性：新前端与独立后端需同步交付。** 缺版本的旧记忆客户端会安全拒绝，不能直接把新前端套用到尚未同步的历史单体网站。

## 验证与证据范围

后端使用 JDK21；前端使用 Node22.23.4、锁定 pnpm11.19.0 安装。原全局 Node 未替换。原始环境和改动后均执行完整后端 verify；前端执行完整 unit、typecheck、design-contract、build。

- Java 大文件测试使用256 MiB堆，49/50/51/128 MiB和1 GiB逐一上传、流式下载与SHA256比对，且检查256块清理、预留释放和重复完成。
- 四个真实 Java 进程使用隔离H2，通过Gateway执行同一尺寸序列、第三块后重新init续传、重复完成、匿名和跨账号拒绝、真实记忆旧版本拒绝。
- 合成分片使用不同索引种子；完整块重排和等长替换会改变最终摘要。测试和下载工具不将1 GiB整文件读入堆内存。
- 新工具 `backend-independent/tools/verify_a_local_workflows.py` 支持重跑；默认51 MiB，全尺寸需显式参数。只创建自己的临时目录和合成账号，退出关闭自身四个进程、删除本轮数据，保留报告和日志。
- 首轮工具使用大量短连接，在Windows出现一次连接建立超时；保留失败记录后，工具改为与浏览器相同的持久连接并重跑通过。这是验证工具的连接策略调整，不是产品网络修复。
- 独立源码审查曾发现过期未知任务、跨卷预留和流式总时限问题，修复后全部关闭。源码审查不代替实际文件系统与MySQL验收。

最终测试计数、最新HTTP测量和浏览器结果见本记录的“最终验收结果”。相关4个既有符号链接测试在当前Windows环境跳过，不能表述为全部测试均执行。
