# Spring Cloud 微服务实施记录

日期：2026-10-26 · 开发版本：`0.1.0-SNAPSHOT`

本轮已将新的独立后端从一个聚合进程改为 **Spring Cloud Gateway + 三个独立业务服务**。采用 Java 21、Spring Boot 4.1.2、Spring Cloud 2025.1.4；组件为 Gateway、LoadBalancer、SimpleDiscoveryClient 和 CircuitBreaker/Resilience4j。[架构与下一步](Spring-Cloud微服务架构与实施计划.md)

## 已实施

| 服务 | 运行与数据所有权 |
| --- | --- |
| platform | 独立 JVM，账号、空间、会话和人工客服，专属 MySQL 库，2 份迁移 |
| content | 独立 JVM，文件/授权/审批/容量与课程，专属库，4 份迁移 |
| intelligence | 独立 JVM，记忆/反馈/知识与任务，专属库，2 份迁移 |
| Gateway | 独立 WebFlux 进程，显式 API/WS 路由，不连接业务数据库 |

原内容与智能模块直接访问账号表、跨库外键和账号行锁已替换为远程身份端口及服务自有 guard。智能服务的课程资格通过内容接口确认；生产依赖只共享纯账号 API，不加载身份、课程的跨服务持久化实现。

调用有连接/读取超时、熔断及有界线程/队列；网络失败不转为授权。网关清除伪造的服务/身份头，拒绝外部内部路径，并签名客户端限流地址。Nginx/双 ECS Docker 模板、随机配置生成器、专属数据库账号初始化、资源限制和部署说明已提供，尚未运行正式镜像或 ECS 环境。

开发期聚合 `cloud-server` 已移除。Maven Enforcer 限制旧后端与跨服务实现依赖；15 个子模块最新一次 `-DskipTests package` 全部成功，并通过这些构建规则。没有执行完整 Maven 测试套件。

## 实际检查

在本机启动四个独立 Java 进程，专用端口 `19093`、`19101`、`19102`、`19103`。临时 MySQL **8.4.11** 只绑定本机 `13336`，新建三个库和三个账号；全部 8 份迁移通过真实 MySQL 执行。

| 经网关检查的流程 | 结果 |
| --- | --- |
| 初始化、登录、管理员/成员管理与角色边界 | 通过 |
| 私有长期记忆、其他空间不可见 | 通过 |
| 反馈幂等/分页/内部备注、旧版本修改冲突 | 通过 |
| 课程知识定向发布、禁止转全站、退出课程拒绝、撤回 | 通过 |
| 本地盘审批、成员授权、容量写满拒绝、删除后释放、跨空间拒绝 | 通过 |
| 客服持久化、WebSocket 就绪/推送、票据重放与退出登录断开 | 通过 |
| 公共内部路径、无服务密钥内部请求、伪造身份头、冲突 Token、非允许 Origin | 均拒绝 |
| 三个服务数据库就绪检查 | 通过 |
| content 数据库账号查询 platform 账号表 | MySQL 以 1142 拒绝 |
| 停止 platform 后，content/intelligence 使用原有效 Token 请求 | 返回 503，无权限降级 |
| platform 恢复后，原 MySQL 会话验证 | 恢复成功 |

WebSocket 代理检查发现上游拒绝发生于浏览器握手之后。已在网关明确使用 1008 关闭授权失败的连接；HTTP 101 不作为认证成功依据。最初自定义 Bean 与框架同名冲突也已修正，最新实际启动与流程通过。

临时账号与密码随机生成，不使用旧管理员或旧库。检查结束后停止四个进程和临时 MySQL，删除临时凭据。未发送邮件、调用外部模型、上传资料到第三方或操作现有 ECS 网站。

## 验证边界

- 这是有限业务流程及微服务边界检查，不是完整测试套件、压测或 Linux/ECS 验收。
- 尚未构建并运行四服务 Docker 镜像，未验证完整浏览器界面；部署配置仅做语法/展开检查。
- 当前一服务一实例。客服票据和文件位置未实现任意副本共享，不能宣称已高可用或支持随意横向扩容。
- 运行时内存预算是初始配置，没有测量并发容量或相对旧版的性能提升。

前端沿用原有主题和角色动画。开发代理增加显式 `CLOUD_BACKEND_MODE=microservices`，新服务保留票据绑定的浏览器 Origin，默认仍使用旧代理逻辑；相关5项已有客服入口/代理/Nginx回归检查通过。Vue脚本/模板、实时工具和Vite配置做了必要语法检查，没有执行整个前端测试套件。

部署文件的 Compose 展开检查通过。新增后端 Docker 构建上下文白名单，仅允许4个可执行JAR及构建配方；运行数据、镜像包和私有配置不进入Git。业务容器用`readyz`检查本服务数据库，网关用`healthz`；这仍不替代镜像实际运行和ECS验收。
