# 部署前接口验收报告

测试日期：2026-10-03。项目：student-cloud-github。数据库：MySQL 8。

后续状态：本文保留修复前的验收事实。接口问题的修复与重新测试结果见 [接口安全修复与回归报告](接口安全修复与回归报告-20261003.md)，不要将本文的历史失败直接当作当前版本结果。

## 1. 验收结论

**暂不通过公网部署验收。** 常规业务回归通过，但新增的安全负向测试实际复现了分享越权和 S3 辅助接口权限缺口。需要先修复这些问题，再进行 Docker / Nginx 环境验收。

本次是测试和部署准备检查，没有修改业务实现，没有执行 Git 提交或推送，也没有在阿里云服务器部署。既有测试通过，不代表所有接口及其异常组合都已安全。

- 未重置、删除或迁移原业务数据库，未删除用户文件。独立测试库和合成文件保留用于后续复现。
- 测试结束后，只关闭核验过启动参数的临时后端 18081 和预览服务 15277。原后端 8080、前端 5173 保留运行。

## 4. 实际复现的问题

### A. 分享条目边界未在所有接口执行——高优先级，上线阻断

测试只选择 `selected.txt` 创建分享，同目录还存在未选择的合成文件及子目录。

| 请求场景 | 预期 | 实际 |
| --- | --- | --- |
| 分享根目录展示 | 只展示选中文件 | HTTP 200，符合预期 |
| 下载选中文件 | 允许 | HTTP 302 → 200，内容匹配 |
| 下载未选中文件 | 拒绝 | HTTP 302 → 200，未分享文件内容精确匹配 |
| 读取未选中子目录 | 拒绝 | HTTP 200 / code 0，返回该目录中的文件名 |

影响：拥有分享链接的人，可以访问本次分享未包含的同目录文件。不是仅前端显示的问题，后端接口可以直接复现。

定位：[ShareLinkFileService.java](../backend/src/main/java/im/tlgxy/cloud/module/share/service/ShareLinkFileService.java)。下载路径没有完整执行分享条目校验；非根目录列表直接按相对路径读取，缺少选中范围约束。

修复验收要求：统一解析和校验分享访问上下文；列表、下载及生成访问链接都只允许选中的文件或明确选中目录的后代。新增同目录未选中文件、未选中子目录、编码路径和边界路径回归用例。

### B. 分享者被禁用后，下载仍可成功——高优先级，上线阻断

禁用测试分享者后：

- 列表返回 HTTP 403 / code 41018，正确拒绝。
- 下载仍返回 HTTP 302 → 200，文件内容精确匹配，错误放行。

定位：同一 ShareLinkFileService 的下载流程没有与列表一致地检查当前分享者状态及授权。

修复验收要求：生成下载链接前重新检查账号、空间和存储授权状态；明确已经签发的下载链接在账号禁用、授权撤销后的失效策略，并测试该策略。

### C. S3 配置辅助接口允许匿名调用及用户指定后端请求目标——高优先级，上线阻断

实际测试 `POST /s3/getBuckets`：

| 调用身份 | HTTP / 业务码 | 后端是否访问测试指定的本机模拟端点 |
| --- | --- | --- |
| 匿名 | 200 / 0 | 是，1 次 |
| 普通成员 USER | 200 / 0 | 是，1 次 |
| 空间管理员 TENANT_ADMIN | 200 / 0 | 是，1 次 |
| 全局管理员 ADMIN | 200 / 0 | 是，1 次 |

共确认 3 次不应被允许的服务端请求。测试证明了未授权调用与后端访问用户所填目标的入口；没有探测外部内网、云元数据或读取真实凭据，不能声称已经验证这些进一步影响。

定位：[S3HelperController.java](../backend/src/main/java/im/tlgxy/cloud/module/storage/controller/helper/S3HelperController.java)。辅助接口不在 `/admin/**` 下，控制器也缺少对应全局管理员鉴权。

修复验收要求：后端强制校验登录身份和实时全局管理员角色；按实际存储接入需求限定出站目标、处理重定向并配置超时和调用频率限制。不能仅靠隐藏前端按钮修复。

同控制器 `/s3/getCorsConfig` 存在相同的静态鉴权缺口，本轮没有对它执行 HTTP 探测。其他第三方存储辅助接口也应一并审查，但尚未实测确认其具体影响。

### D. 非法下载路径仍先签发链接——中优先级

相同边界路径输入：列表返回 HTTP 400 / code 41009；下载接口却先返回 HTTP 302，后续下载 HTTP 500。

本次没有读取到越界文件内容，因此**不能描述为已成功实现文件系统穿越**。已确认的问题是下载入口校验不一致，非法路径不应先获得访问链接。

### E. 分享密码长度缺少请求校验——中优先级

19 字符合成分享密码使创建接口返回 HTTP 500 / code 50000。隔离服务日志定位为 MySQL `share_link.password` 列长度超限。

定位：[CreateShareLinkRequest.java](../backend/src/main/java/im/tlgxy/cloud/module/share/model/request/CreateShareLinkRequest.java)。应统一前后端与数据库长度约束，并返回可理解的 HTTP 4xx 参数错误。

### F. 拒绝访问的状态码一致性——低优先级

普通成员访问空间管理员总览被拒绝，但返回 HTTP 400 / code 50000，而不是语义明确的 HTTP 403。本轮没有发现此请求越权成功，可在权限修复时统一响应规范。

## 6. Docker 部署准备检查

以下为仓库静态检查，不是已完成的 Docker 实机验收：

1. 当前只有后端示例 Dockerfile，未发现完整 Compose、前端容器或实际 Nginx 配置文件。因此还不能把仓库当作已验证的一键完整站点部署包。
2. 前端生产构建通过，但后端 JAR 不包含前端首页。需要由 Nginx 等服务托管前端 dist，并正确代理后端。
3. 容器中不能沿用数据库地址 `localhost:3306` 指向另一 MySQL 容器；需要使用配置的数据库服务地址。密码等秘密应通过受保护的运行配置提供，不进入镜像或 Git。
4. 共享空间目录应显式配置，例如 `STUDENT_CLOUD_WORKSPACE_STORAGE_ROOT=/data/workspaces`，并挂载持久卷、校验运行用户写权限。用户文件、数据库和必要的应用持久状态不能只放在容器可写层。
5. 若迁移现有 Windows 数据库，本地存储配置中的 Windows 绝对路径需要随文件迁移转换为 Linux 容器路径。仅设置新共享盘根目录变量，不会自动转换旧存储记录。
6. 现有 Ubuntu 原生部署指南的日志路径是 `/var/log/student-cloud`；共享盘默认推导为 `/var/log/workspaces`，但 systemd 仅放行 `/var/lib/student-cloud` 与 `/var/log/student-cloud` 写入。按旧示例直接部署，新空间共享盘创建可能失败。应显式设共享盘根目录到允许写入的位置；Docker 则使用已挂载的数据目录。
7. 实际数据库迁移已到 V67，现有指南部分仍描述 V60；前端 package.json 要求 Node >=22.13.0；角色也应包含空间管理员。不要照旧版环境说明直接执行。
8. 邮箱注册需要真实 QQ SMTP 配置及稳定的 `MAIL_CODE_SECRET`。当前代码在未设置该 secret 时每次启动随机生成，待使用验证码可能因重启失效。
9. Nginx 需要验证 SPA 路由、接口路径保留、文件上传大小限制、SSE 不缓冲及超时设置。只检查直接访问后端的 SSE，不能替代经过 Nginx 的真实验证。
10. 没有确认可直接使用的容器健康检查配置。上线包需要明确健康/就绪检查、非 root 运行、重启策略和数据备份恢复流程。

正向检查：当前 JAR 未包含本地私密配置；存在后端 `.dockerignore` 排除本地秘密文件；生产配置关闭接口文档，Flyway 清库能力禁用。这些措施有帮助，但不能抵消上述接口安全缺陷。
