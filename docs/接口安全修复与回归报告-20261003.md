# 接口安全修复与回归报告

日期：2026-10-03。项目：student-cloud-github。

## 结论

前次验收发现的分享越权、分享者禁用后的新下载、S3 辅助接口未授权调用、非法路径先签发下载地址和分享密码超长错误，已完成代码修复并通过回归。

修复版后端已打包并在本机 8080 启动，前端保持在 5173 运行。未部署服务器、未提交或推送 Git。

**已按用户确认轮换业务下载密钥并重启后端。** 仅更新 `student_cloud.system_config` 中唯一的 `rsaHexKey` 记录一次。新临时/永久代理下载实测 HTTP 200；不同密钥票据实测 HTTP 403。旧分享下载地址与普通下载地址使用相同格式，无法可靠区分，因此本次轮换也会撤销旧普通下载、预览和永久代理直链，需要刷新页面重新获取。

Docker / Nginx / HTTPS / 真实云服务的服务器验收也尚未完成，不能将本轮本机测试等同于完整公网部署验收。

### 分享前后端联调

- 前端保留后端签发的文件 URL，不再把所有文件重新改成无上下文的下载入口，也不为后端已拒绝的 null URL 生成可点击链接。
- 目录密码仍需在签发票据前验证。实际测试确认无密码的受保护目录和下载被拒绝，提供正确目录密码后列表和下载正常。
- 直接下载入口支持可选 `folderPassword`；OnlyOffice 配置查询也透传目录密码。
- 前端构造分享页面链接时，对分享密码使用 URI 编码，保留 `&`、`+`、`?`、`#` 等字符。
- 分享创建保留原始文件名，不再 trim 后误改合法含空格的名称。
- 校验失败交给统一异常处理，保留 HTTP 4xx 和业务码；代理下载签名失败日志不再记录完整签名。

### S3 辅助请求

只有全局 ADMIN 可使用全局存储配置辅助入口，普通空间管理员仍可使用已有共享盘，但不能借辅助接口配置全局第三方存储。

S3 辅助入口默认只接受公网 HTTP/HTTPS 端点，推荐 HTTPS。拒绝回环、私网、link-local、保留地址、非根路径、userinfo、query、fragment 和混合公网/私网 DNS。已解析地址固定到实际连接，防止验证后重新解析到其他地址。

连接超时 3 秒、连接获取 2 秒、socket 8 秒、单次调用 10 秒、总调用 15 秒，不自动重试；客户端和响应及时关闭。同类辅助接口也移除无限读取超时并禁止重定向。正式 OAuth 回调不在本次辅助路径限制范围内。

### 业务下载密钥轮换

- 只读核实密钥用途：仅用于普通/永久代理下载 AES 票据及 `SHARE1` 的 HMAC，未发现文件内容、数据库密码或存储凭据依赖它做持久加密。
- 核实当前数据库是 `student_cloud`，密钥配置恰好 1 行，未启用 Redis 配置缓存。以旧值条件限制单行更新，MySQL 安全随机生成新密钥；密钥只在进程内读取，没有打印、写入文档或提交 Git。
- 轮换前，合成测试文件的临时和永久票据均 HTTP 200。轮换后，新票据均 HTTP 200 且内容完全匹配；不同密钥签发的两类票据均 HTTP 403。合成文件验证完成后已删除，没有读取或删除用户文件。
- 第一次就绪检查误把接口的字符串业务码 `"0"` 当成数字 `0`，导致验证脚本超时，但密钥已经更新且服务已恢复。已修正判断并采用仅验证模式恢复，**没有再次轮换**。另一次前端探测用了 JSON Accept，Vite 对该请求未提供 SPA 路由回退；改用浏览器 HTML 请求后登录页 HTTP 200，此项不是网页故障。
- **证据限制：原始旧业务票据没有持久保存，初次验证进程超时退出后无法原样重放。** 不把补测的“不同密钥票据 403”冒充“同一旧业务票据重放 403”。旧密钥确实改变的比较在更新进程内完成；普通、永久和 `SHARE1` 旧票据撤销另有密钥轮换单元回归覆盖。
- 重启后当前数据库密钥可正常签发被业务后端接受的下载票据，证明后端已使用当前密钥；本轮没有创建业务分享或短链，现有记录数量均未变化，不能据此声称实测了真实历史分享/短链的打开过程。
- 轮换后另行重跑 `ShareDownloadTokenUtilsTest`：3 项通过、0 失败、0 跳过，覆盖普通、永久及分享票据的旧密钥撤销，BUILD SUCCESS。该定向重跑不是另一次完整后端回归。

## 兼容性与发布前待办

1. **已完成：轮换下载签名密钥。** 在本机业务库受控更新 `system_config.rsaHexKey` 后重启，旧缓存不再生效。旧下载/预览 URL 需重新获取；不要在部署时恢复旧密钥备份，否则旧票据可能重新有效。本机操作不代表阿里云上的其他数据库也已轮换。
2. 轮换不会删除文件、分享页或短链记录。普通短链入口按记录重新生成访问地址，旧已复制的底层下载直链需重新获取；不应承诺所有历史链接形式都无影响。
3. 新分享内容统一走服务器代理，服务器承担下载带宽。下载开始前及后续 Range 请求重新鉴权，已经开始的单次文件传输不强制中断。
4. 新分享票据最多有效 30 分钟，过期后需刷新分享页面获取新地址。普通非分享下载保持既有签名策略。
5. 不支持代理传输的存储实现不能生成这种可实时撤销的分享下载地址，会明确报错；真实第三方存储的代理下载兼容性尚需服务器联调。
6. 内网 MinIO / 私网 S3 的“自动获取桶/CORS”默认被拒绝，没有添加放行开关；需评估可信内网接入方案后再单独支持，不能关闭 SSRF 防护绕过。
7. 发布前继续完成 Docker / Nginx、Linux 存储路径迁移、持久卷、QQ SMTP、HTTPS、SSE、上传大小限制及重启/备份恢复验证，参照前次报告中的部署检查。
