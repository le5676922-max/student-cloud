# 文件业务升级实施记录

本轮采用文件管理产品中成熟的业务思路，在独立后端实现；没有引入 Tank 的运行代码。保持现有页面主题，仍为平台、内容、智能三个服务与 Gateway。没有部署到服务器，也没有修改旧 `backend/`。

## 已接通的功能

| 业务 | 使用方法与实际行为 |
| --- | --- |
| 目录元数据 | 同目录在10秒快照有效期内复用结果；写入立即失效，手动刷新重新扫描。保留完整文件时间精度。原页面继续使用列表，另提供SQL分页与文件名查询API。 |
| 可恢复上传 | 独立后端的大文件走4MiB分块，记录摘要与已收分块；重新选择同一文件、同一授权目录时只补缺块。完成可重复查询，不覆盖已有目标。 |
| 回收站 | 文件页删除进入个人回收站，保留7天并仍计容量；回收站可恢复或确认彻底删除。恢复遇同名文件拒绝覆盖。 |
| 成员权限预设 | 空间管理员为选中成员选择“只读”“上传协作”或“自定义”；只设置该成员、当前存储源允许授予的权限交集，容量与目录范围单独管理。 |
| 受控分享 | 选择单个文件，明确本空间成员或指定课程成员，创建有效期1/7/30天的分享；接收者必须登录，下载前重新核验成员资格和来源。可撤销，源变化后旧分享拒绝继续提供。 |
| 管理统计 | 全局管理员查看全局，空间管理员查看本空间与自己创建的课程。显示存储源、资料、暂存任务、分享、回收站及趋势；不可用显示未知，不冒充0。 |

## 容量、隐私与异常处理

- 当前 LOCAL 文件内核单文件上限50MiB；续传会话24小时、每人最多3个活动会话和100MiB预留，全部暂存预留1GiB。上传暂存与云盘、课程目录互不重叠，任务绑定稳定内容节点标识。
- 初始化上传时，远程身份查询和容量遍历不持有全局数据库预算锁；SQL负责会话和预留协调。接收请求体不持有SQL事务。
- 发布前再次检查授权、目标与额度；出现保存结果不确定时保留状态要求核查，不自动重放文件副作用。
- 回收站藏在原个人授权根内，不能经普通文件路径访问或被重新挂载为云盘。列表只展示本人、当前存储源和授权根的记录。
- 回收、恢复和清理先提交操作意图。SQL与文件系统不能共同提交，异常保留不确定状态，不假装成功；恢复中也保持容量统计。到期清理每次最多10项。
- 分享是有界单文件；用户登录凭据只在请求头中使用，链接不含 Token。不接入匿名提取码或把文件URL发送给外部Office预览。
- 接口路径使用统一规范，拒绝矩阵参数和编码别名，防止绕过请求体预算；虚拟文件名仍可在查询参数或请求体中传递。

## 验证结果

文件业务收尾时，完整 Maven `verify` 运行300项测试：296通过，4项因Windows符号链接条件跳过，0失败/错误。前端完整797项通过；随后上传会话切换与分享交互修正的57项定向测试通过；前端生产构建通过。后续知识库修改应重新记录最终测试结果，不能沿用这份中间数字。

临时MySQL8.4.11、三个专属数据库账号、四个真实Java进程通过Gateway完成10组流程，覆盖账号与匿名拒绝、容量审批、Agent确认归档、反馈与私有来源限制、重复检查、课程邀请码人数上限/上传审批、全局角色边界、元数据查询、分享撤销、私人回收恢复、三块上传及完成重试、字节一致性和统计。

这些联调用本机合成模型，不代表真实外部模型、QQ SMTP、Linux符号链接或服务器部署已验收。测试进程、临时MySQL和生成的凭据均由脚本清理。

## 当前限制

目录索引只缓存元数据，不能据此授予读取权限；每次实际文件操作仍检查源和权限。原文件界面尚未改为服务端分页，不能将新增分页API描述为整站分页已替换。趋势按已保存业务记录的创建时间聚合，不能当作全量操作审计或真实磁盘容量曲线。

目前独立后端只有LOCAL驱动；多个内容实例不能将不同节点本地盘当成共享文件系统。Redis业务缓存、远程存储驱动、完整压力测试和ECS部署仍是后续工作，未据此宣称性能优于其它项目。

主要实现位于 `backend-independent/cloud-drive-application`、`cloud-drive` 和 `cloud-content-service`，新增内容迁移V8–V11；界面新增受控分享、回收站与管理统计面板。可复用真实验收脚本为 `backend-independent/tools/verify_business_workflows.py`。
