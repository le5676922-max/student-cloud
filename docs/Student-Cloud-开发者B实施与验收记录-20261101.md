默认关闭新写入机制，避免未验收的升级直接改变线上规则。不存在“只改前端开关就能获得服务端权限”。

| --- | --- | --- |

## 真实数据库验证

本机实测 MySQL **8.0.45**，不是计划书要求的 8.4。只创建随机命名的隔离测试库，执行后删除；连接密码仅用于进程环境，没有写入项目或文档。

完整 Maven `verify`：681 项，677 通过、0 失败/错误、4 项因 Windows 符号链接能力跳过。前端：1011 项全部通过，类型检查、生产构建与设计契约检查退出码均为 0。构建仍有大于 500 kB 的分包提示和依赖 CSS 压缩警告；通过构建不等于这些性能事项已消失。

四个真实 Java 进程的隔离联调亦通过：新迁移启动、匿名拒绝、仅本机 SMTP 验证注册、真实新建目录与本人收据、双向空间交接与旧会话撤销、交接后双方仍只见各自目录、新管理员调整前任容量不移动私人根，以及资料来源缺失时真实返回 503。联调使用独立 H2 内存库；测试进程和邮件夹具均已停止，没有向外部模型发请求。这不能替代 MySQL 跨服务联调或浏览器视觉验收。

已观察的账本场景：

1. 未校准占用返回未知，不是零。
2. 独立连接/事务管理器并发：200 MiB 配额，两次各预留 128 MiB，只成功一次。
3. 重复结算仅增加一次已用容量与一条结算流水。
4. 降低配额不删除已有字节，阻止新写入。
5. 重新创建服务实例及超过有效时间后，不明预留仍保留。
6. 不能通过校准抹掉不明预留；其他主体不能结算本人记录。
7. 零字节增长的持久意图同样阻止并发校准；未扫描目录的零增长操作不制造“已知零占用”。

这不等于 MySQL 8.4、断电/强杀、OSS 或向量检索的验收。

## 安全与恢复

- 已发布文件后发生 SQL/网络错误，保留“不确定”结果，不提示直接再传一次。
- 零字节增长的移动、回收、清理也持久登记意图，校准不能穿过仍在执行的操作。
- 保留个人目录和权限，不把管理交接变成私人文件迁移；角色只是当前职能，私人命名空间绑定不可变账号 ID。
- 撤权、换账号、换云盘后丢弃旧响应；普通网络错误与 401/403 分开处理。
- 回滚脚本只用于源代码副本，不删除数据库、用户文件或审计流水。已经执行的迁移与交接状态需要独立业务恢复，不能靠覆盖源码回退。
