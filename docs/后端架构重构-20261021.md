# 后端渐进式架构重构与验证（2026-10-21）

## 范围

本轮在原项目 `student-cloud-github/backend` 内调整后端依赖和职责，不替换项目、不修改刚恢复的登录界面或小芽。已有前端工作区改动保留，不因后端分层而重新设计页面。

这是模块化单体内部的一段迁移，不是微服务拆分，也不代表已将全部历史实现替换成独立内核。原有版权、许可及来源说明继续保留。

## 目录查询：控制器与应用编排分离

```text
FileController（HTTP 参数、当前用户、AjaxJson 响应）
  └─ DirectoryListingApplicationService（普通/快速分页编排）
       ├─ StorageDriverRegistry
       │    └─ StorageContextDriverRegistry → 现有文件驱动
       ├─ DirectoryAccessGuard / FileChain（现有权限、密码和过滤规则）
       └─ DirectoryMetadataCache / NativeDirectoryCursorService
```

- `/api/storage/files` 由应用服务统一协调目录缓存、权限处理、分页游标和当前页下载链接；控制器不再承载这套流程。
- `/api/storage/list`、`/api/storage/file/item` 及其请求、响应类型不变，单文件密码注解保留。
- 驱动解析通过构造器注入的 `StorageDriverRegistry` 访问，控制器和目录应用服务不直接引用静态存储注册表。
- 保留权限处理后分页、签名前复查授权、快速分页前密码校验，以及游标与账号、根目录、缓存代次的绑定。

该端口仍返回原有 `AbstractBaseFileService`。驱动的当前用户根目录和责任链仍间接读取现有会话/分享上下文；应用服务的 `actor` 参数不意味着可以脱离原请求上下文任意冒充账号执行后台任务。

## 学习资料：以业务端口隔离 AI 实现

| 学习模块拥有的端口 | 当前适配器 | 职责 |
| --- | --- | --- |
| `LearningFileAccess` | `LearningFileReader` | 重新校验文件权限、受限读取和完整内容指纹 |
| `LearningContentExtractor` | `AiLearningContentExtractor` | 调用原解析器，映射正文、覆盖字数、页数、截断和提示共六项字段 |
| `LearningEmbeddingGateway` | `LearningEmbeddingClient` | 可选 embedding 配置和批量嵌入请求 |

`LearningLibraryService` 和 `LearningSemanticIndex` 依赖上述接口，不再依赖 AI 模块的具体客户端或提取结果类型。路径规范化原样移至 `LearningDocumentPath`，旧 `LearningFileReader.normalizePath` 保留委托，避免破坏现有调用。

既有的 5 MiB 文件限制、实时授权检查、文件变更失效、解析并发限制、短写入事务、向量预算和关键词回退均保留。本轮不更换模型、不发送真实模型请求、不新增 OCR 依赖。

## 兼容性与尚未迁移的边界

- REST 路径、业务 DTO、数据库表和 Flyway 迁移不变，无需为这次分层重建业务库。
- `LearningLibraryService` 仍使用用户服务、MyBatis、事务模板及当前账号工具；文件适配器仍使用旧存储上下文及授权、过滤、密码服务。
- 现有驱动 SPI、下载/上传等其他文件流程尚未整体迁移；这不是“后端全部独立化完成”。
- 仅调整依赖方向，不凭此声称数据库请求量、响应延迟或吞吐提升。后续性能优化应以真实接口测量为依据。
- 当前仍按单后端部署；本轮未改变 Redis 或多实例一致性方案，也未变更 Docker/Nginx 配置。

## 验证

本轮结果如下。MySQL 工作流是在全量验证之后单独重跑，不应与全量用例数相加解释为不同用例。

| 验证 | 结果 | 环境与限制 |
| --- | --- | --- |
| 后端 `mvn verify` | 共 751 项；734 通过、17 跳过、0 失败、0 错误；构建成功 | JDK 21；HTTP 集成使用临时 SQLite 测试配置 |
| 独立 MySQL `CloudWorkflowTest` | 16/16 通过，0 跳过 | 本机 MySQL 8.0.45，新建专用空库；成功执行原有 72 项迁移至 V72 |
| 本轮新增架构/适配器回归 | 25/25 通过 | 已包含在 751 项之内，不是额外累计数 |
| JAR 内容检查 | 新应用服务、端口和适配器存在 | 未打入装配测试类或 `application-local-secrets.properties` 文件 |
| 前端保护文件校验 | 与本轮开始时一致 | 登录页、登录样式、角色动画组件、小芽组件的 SHA-256 相同 |

17 项跳过包括：Redis 实例集成 9 项（未启用）、真实 DeepSeek 调用 3 项（未启用）、搜索基准 1 项（未启用）、当前 Windows 测试环境无法创建符号链接的 4 项。不能把这些跳过解释为通过；符号链接用例仍应在部署目标 Linux 环境补跑。

MySQL 重跑覆盖真实 HTTP 的初始化/登录、文件上传下载、目录分页、分享与授权撤销、角色/空间隔离、学习索引及 Agent 确认流程等。使用合成测试账号和文件，关闭真实模型调用，不借用业务数据。新测试库保留为隔离测试产物，未删除现有数据库或业务文件。

本轮没有执行浏览器视觉验收、线上压力测试或 Docker 部署，也没有复验真实外部云存储、SMTP、OCR 和收费模型服务；不能据此宣称整个网站已完成生产验收。

### 新增回归与护栏

- `BackendModuleBoundaryTest`：字节码层检查学习端口、目录控制器依赖方向，以及既有 HTTP 映射和密码注解。
- `DirectoryListingApplicationServiceTest`、`FileControllerDelegationTest`、`StorageContextDriverRegistryTest`：无效源、传统驱动、身份与游标绑定、响应包装和驱动解析。
- `AiLearningContentExtractorTest`、`LearningFileAccessFreshnessTest`、`LearningPortWiringTest`：六字段映射、权限撤销/内容变化、真实适配器唯一装配和禁用 embedding 回退。
- 保留并运行现有目录元数据、原生分页、学习权限、搜索预算及并发写入测试。

隔离装配测试通过 `ApplicationContextRunner` 显式注册真实适配器和测试依赖，不声明可能进入旧组件扫描的额外配置类，不覆盖生产配置。完整 HTTP 工作流使用测试配置与临时文件，不启动用户正在使用的站点。

### 复现命令

在 `backend` 目录使用 JDK 21 和 Maven：

```powershell
# 默认 HTTP 集成用临时 SQLite 测试库；不是修改生产数据库类型。
# 不设置 CLOUD_*_TEST_MYSQL_URL，不设置真实模型测试开关。
mvn --no-transfer-progress -Dstudent.cloud.redis.integration=false -Dlearning.benchmark=false verify
```

独立 MySQL 工作流使用 `CloudWorkflowTest`。测试只接受环回地址、3306 端口以及 `student_cloud_role_test_` 前缀的专用库，**不能填写业务库**。先创建全新空库，再在测试进程环境设置 `CLOUD_TEST_MYSQL_URL`、`CLOUD_TEST_MYSQL_USER`、`CLOUD_TEST_MYSQL_PASSWORD`，执行：

```powershell
# 凭据只传入测试进程，不写入源码，也不在命令行参数中展开密码。
mvn --no-transfer-progress -Dtest=CloudWorkflowTest test
```

不要在同一个 `target` 目录同时运行多个 Maven 测试进程。测试通过并不表示已启动本机服务、更新线上部署或推送 GitHub。
