# OSS / S3 接入与业务优化实施记录

> 日期：2026-10-27。范围是独立后端的远程存储实现与本地联调；没有部署线上网站，也没有推送 GitHub。

本轮按确认的方案，将阿里云 OSS 和 S3 兼容协议接入现有 Student Cloud。保留三个业务后端与 Gateway，保留前端主题；只调整存储表单、能力入口和操作反馈。业务参考分析与实现代码分离，没有引入旧后端运行时。

## 测试发现并修复的问题

1. 本地存储别名查询参数不兼容、初始停用未落库、有关联申请历史时删除失败原因不清晰、权限编辑锁顺序不一致。
2. 保存前异步校验期间切换账号、路由或表单，旧请求仍可能提交或更新新页面。现在请求使用快照，旧响应失效并取消。
3. 原前端把独立后端空间管理员一律限制为不能编辑、启停连接。现仅保留本地源的全局管理限制，允许其管理自己空间的远程源。
4. 远程保存与上传缺少共同锁边界，配置可能在发布窗口被改变。现统一 mount → guard 的锁顺序，并在短事务内完成版本复核。
5. 旧保存请求可能重新启用刚被停用的源。现保存携带并核对独立的 mountRevision，停用不改变用于正向核查的连接版本。
6. 上传成功后的客户端关闭异常会误改任务终态；读取失败后的关闭异常会掩盖业务错误并泄漏并发名额。现精确释放资源，完成状态不回退。
7. 截断下载和无进度读取未明确失败。现在校验已声明长度，并为持续空读取设置预算。
8. S3 的内存流探针通过，但实际暂存文件流创建目录失败。真实 SDK 需要重复读取请求体，文件流不支持 reset。现以私有、有界的可重复文件请求体适配，并验证实际长度和精确清理；零字节与 512 KiB 文件流均有回归。

S3 请求体适配增加一份最多 50 MiB 的临时磁盘 I/O，以避免将整个文件装入堆内存。应用层限制远程读写并发与探针并发，临时目录必须与可浏览目录隔离。

## 使用与边界

本地入口：<http://127.0.0.1:5173/>。添加方法和最小权限见 [OSS与S3远程存储接入指南](OSS与S3远程存储接入指南.md)，完整帮助见 [知识库内容与维护手册](知识库内容与维护手册.md)。

- **尚未使用真实 OSS/S3 云账号和生产 Bucket 验收。** 本机协议夹具不能证明任意云厂商、IAM 策略、网络或实际 Bucket 配置都兼容。
- 本轮未对 QQ SMTP、ECS 高并发或真实外部模型进行新验收；知识改进是检索内容与流程升级，不是模型微调或向量训练。
- 当前浏览器自动化被本机 Work 设置关闭，因此本轮新增界面没有重新做浏览器点击验收；使用前端回归、HTTP 合约和实际 API 联调验证，没有冒称已完成当前 UI 的人工检查。
- 仅采用官方公开端点或运维精确允许的自建 origin；自建域名属于可信运维配置，当前不做 DNS 地址固定。
- 探针清理失败或响应丢失会报告失败和随机对象 key，不自动重试或递归清理；探针目前没有独立持久清理队列，需管理员核查。
- 用户文件的 PUBLISHING / UNCERTAIN 写入有持久记录和正向核查；证据缺失时继续冻结，没有强制重放或一键忽略结果的入口。
