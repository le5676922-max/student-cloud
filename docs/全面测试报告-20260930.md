## 5. 响应耗时样本

2026-09-30，本机接口每项 20 次请求、并发 4；数据量较小，不代表公网延迟或服务器最大承载量。

| 接口 | 中位数 | P95 | 最大值 |
| --- | ---: | ---: | ---: |
| 全局站点配置 | 6.89 ms | 14.47 ms | 14.78 ms |
| 全局总览 | 16.53 ms | 17.11 ms | 17.35 ms |
| 文件列表 | 13.42 ms | 102.92 ms | 103.54 ms |

文件列表本次存在约 100 ms 的尾延迟，不能只报告中位数。此前一次样本 P95 为 15.50 ms，说明本机短样本也会波动；尚未通过长时间压测确认原因。

- 真实模型 HTTP：普通流式回答总耗时 880 ms（3 个 token 事件）；只读工具调用并回答 906 ms（23 个 token 事件）。不是首 token 延迟，也不代表复杂任务平均耗时。
- RAG 局部磁盘校验基准：30 份各 5 MiB 文件，选取 5 份候选，热文件系统 7 次采样，中位数全扫描 192.67 ms、候选校验 35.76 ms；读取量由 150 MiB 降至 25 MiB。这不是完整 RAG 或模型响应耗时。
- 当前样本不足以证明“必须引入 Redis”；优先排查真实业务慢请求、数据库索引和缓存命中，再评估共享缓存收益。

## 6. 尚未解决的问题与上线边界

### 优先处理

1. 前端依赖审计输出：2 critical、54 high、67 moderate、9 low。该计数来自 `pnpm audit --prod`，不能直接等同于网站中可利用漏洞数量；需要逐项核实依赖链和运行时可达性，再升级并回归。尚未完成这项治理。
2. 登录页“记住密码”仍将密码保存在浏览器 localStorage；应改为只记用户名或使用受控会话保持，不能把明文密码长期存入浏览器。本轮测试未勾选记住密码。
3. 当前本机后端配置按此前要求保留数据库密码字面量，打包 JAR 也可能包含它。发布/上传前必须完成凭据外置和泄漏检查，不能直接公开当前源码或构建产物。

### 规范与性能债务

- 全量前端 ESLint 未通过：12,558 条错误、624 条警告，主要为历史格式问题，也有未使用变量、组件修改 props、外部全局声明等。未用关闭规则或批量无关格式化掩盖结果。
- 构建仍有大 chunk；入口约 1,144.53 kB、PDF 组件约 2,416.19 kB（构建输出尺寸，不是 gzip 网络传输量）。需结合加载瀑布评估首屏、按需加载和缓存。
- 登录日志配置存在可记录密码的模式，应在上线安全检查中确认实际配置并移除明文记录能力；本轮未声称业务库已经发生密码日志泄漏。
- 回答质量：简洁模式下，一次要求长清单的无害问题出现生硬拒绝；切到详细模式后能正常生成长文。建议补充回答风格评测，避免把“简洁”误解为拒绝用户的详细说明需求。
