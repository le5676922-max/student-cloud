# 小芽的RAG、Wiki与长期记忆

知识ID：`knowledge-memory-guide`。适用：所有登录用户；2026-10-30独立后端。本页明确区分当前能力和设计目标。

## 三者的分工

RAG在提问时查找相关原文片段，适合核对实际文件。Wiki在资料加入或变更时先整理概念、主题与关联，方便以后重复使用；它仍要保留真实来源。Memory只保存某个用户的稳定偏好或背景，不是所有课程共用的事实库。

当前独立后端使用关键词排序、人工审核知识及个人学习资料片段，没有因此自动具备embedding向量检索、任意课程Wiki编译或模型参数训练。结构化产品知识是Wiki的种子，不能把它宣传为已经完成全量自动Wiki。

## 一次资料问答

选择要使用的课程及问题范围→勾选本轮私有资料处理→发送问题→查看结论与引用→点回原始资料核对。源权限与状态在读取及回答完成前复核。没有命中时明确说明，不编造页码、出处或文件内容。

Wiki上线后也应保持原文核验通路：原文精确查询直接查RAG，多资料综合先查Wiki，再核对关键证据。资料过期、来源冲突或无法定位时回源，不把旧Wiki当作永远正确。用户关闭Wiki后应仍可使用基础文件操作和原文检索。

## 保存和使用记忆

本人通过长期记忆面板保存内容，可以查看、编辑、停用和删除。当前最多50条，每条500字符；不要保存密码、验证码、密钥、身份证件或他人的个人信息。保存“回答简短一点”不代表授权助手对外共享私人文件。

新版规则：未选择本轮私有上下文时，不把记忆发给外部模型；选择后也只选取与本次提问相关的本人条目，而不是机械发送最新十条。相关性首期是本地词法匹配，不声称等同语义理解；未命中时可由用户补充上下文。

停用后保留本人的管理入口，但对话不使用记忆。删除和关闭不能撤回已经向外部服务发送的历史请求，也不能承诺从已训练的模型中精确抹去某条知识，所以本项目不会把记忆自动作为训练样本。

## Wiki的安全更新目标

拟采用的流程是：授权来源→受限提取→摘要去重→生成候选→校验引用与范围→按策略发布。原始资料不被模型改写；页面有不可变修订、来源版本和关联。资料撤权先让依赖页不可检索，再异步重建。

冲突记录须保留两边证据及适用时间，不能用自报“置信度90%”覆盖另一份资料。模型答案不能再次作为独立证据循环引用，避免错误越来越像事实。

## 自动评测和微调

先评测资料是否命中、引用是否支持结论、权限是否隔离、任务是否真的完成，再决定是否优化。合成模型测试只能证明接口和安全契约，不证明真实模型答案质量。

周期性任务应先产出知识过期、坏例和训练资格报告；资料内容更新优先更新知识库，工具误用优先改工具契约与提示。外部微调必须有供应商能力、合格且获准的数据、预算和留出评测；当前不会按日历自动上传成员对话训练。

依据：`MemoryService`、`KnowledgeTextMatcher`、`ChatService`、`ReviewedKnowledgeService`、`LearningLibraryService`及本次AI云盘设计提案。
