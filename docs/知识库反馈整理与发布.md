# 小芽知识库：从“未解决”到审核发布

这是一套知识整理流程，不是模型微调。成员点击“没有解决”只提交选中的一组问答；全局管理员核对正确答案，可选择 AI 辅助润色，人工确认后发布。发布内容实际加入小芽的 RAG 检索，后续相关问题可以引用这些知识。

## 1. 在管理页面整理

1. 全局管理员进入 **日志与诊断 → AI 反馈**。
2. 打开反馈，查看问题和折叠的原 AI 回答。原回答仍视为未核验内容，不会自动填入正确答案。
3. 输入核对后的正确答案。可点击 **AI 辅助润色**：只将脱敏的问题和当前人工修订发给已配置的 AI 服务，不发送账号资料、完整会话、附件或原 AI 回答。
4. AI 结果先作为草稿展示。核对并点击“采用草稿，继续编辑”，必要时修改，再将处理状态设为“已整理”，保存。
5. 重新打开反馈，在“知识库整理”中确认范围，点击 **确认发布到知识库**。
6. 后续可查看版本记录或撤回当前版本。撤回后新的检索立即停止使用该版本，已发生的历史对话不会因此被改写。

保存整理、导出问答、AI 润色都不会自动发布。发布与转人工客服也相互独立。

## 2. 发布范围与隐私

| 范围 | 可见账号 | 规则 |
| --- | --- | --- |
| 所属空间 | 原反馈所属空间的启用成员、空间管理员 | 普通反馈默认此范围；其他空间不能检索 |
| 原课程 | 当前仍有该课程访问权的成员及创建者，允许跨空间 | 带课程来源的反馈只能发布回原课程，禁止扩大到整个空间或全站 |
| 全站通用 | 启用账号 | 仅普通反馈可选，须额外确认通用说明且不含个人资料、课程专属内容或私人文件内容 |

账号状态、工作空间状态和课程访问权都在检索时校验。仅在同一工作空间不等于加入课程；退课、移除、课程暂停或创建者失效会停止课程知识检索。全局管理员可在整理页面核查知识，但小芽的普通对话不会因此自动读取所有课程的私人问答。

服务端会隐藏常见 API 密钥、Bearer 令牌、密码键值、邮箱、手机号和账号 ID。自动脱敏无法判断所有私人信息，发布前仍需检查姓名、业务细节和文件正文。源账号或反馈删除后，关联发布与版本记录随之删除。

## 3. 批量整理脚本

脚本为 `scripts/curate-knowledge.py`，只依赖 Python 3 标准库。Windows 可用 `py`，Ubuntu 可用 `python3`。通过隐藏提示输入管理员密码，密码和登录令牌不会写入命令行、复核文件或日志。脚本不处理图形验证码、双因素认证等交互，启用此类验证时使用管理页面。

### 导出已整理的问答

```powershell
# Windows：本地站点地址按实际前后端入口调整。
# 复核文件包含问答正文，放在私有目录，不要提交到 Git。
py scripts/curate-knowledge.py export `
  --base-url http://127.0.0.1:5173 `
  --username 你的全局管理员账号 `
  --file .codex-tmp/kb-review.json `
  --limit 5
```

```bash
# Ubuntu：远程站点必须 HTTPS，HTTP 只接受本机回环地址。
python3 scripts/curate-knowledge.py export \
  --base-url https://你的域名 \
  --username 你的全局管理员账号 \
  --file "$HOME/private-kb-review.json" \
  --limit 5
```

如果明确需要调用 AI 润色，可在 export 命令末尾加 `--ai`。这会调用已经配置的外部模型服务，可能产生其正常 API 费用，每批限制最多 5 条以配合整理接口限流。默认命令不调用模型。脚本不会自动采纳 AI 草稿：候选保存在 `candidateAnswer`，正式答案仍在 `answer`。

### 人工复核文件

```json
{
  "schema": 1,
  "entries": [
    {
      "feedbackId": "由脚本生成的32位反馈ID",
      "expectedUpdatedAt": 由脚本读取的时间戳,
      "expectedVersion": 0,
      "title": "知识标题",
      "question": "原问题，供复核参考",
      "answer": "人工核对后的正式答案",
      "scope": "TENANT",
      "confirmGlobal": false,
      "reviewed": true
    }
  ]
}
```

上面是字段说明，时间戳位置需保留脚本生成的数字才能构成有效 JSON。不要编造 ID、时间戳或版本；它们用于拒绝过期修改。

- 检查 `answer`，如需采用 AI 建议，请人工核对后再从 `candidateAnswer` 复制修改。
- 检查范围；普通反馈默认 `TENANT`，课程来源默认且只能 `COURSE`。
- 通用帮助若确实需要全站使用，显式改为 `GLOBAL` 并设置 `confirmGlobal: true`。
- 每条核对完成后，才将 `reviewed` 改为 `true`。

### 批量发布

```powershell
py scripts/curate-knowledge.py publish `
  --base-url http://127.0.0.1:5173 `
  --username 你的全局管理员账号 `
  --file .codex-tmp/kb-review.json
```

脚本再次核查服务器来源和版本，要求输入 `PUBLISH`。若答案有修改，先保存人工修订并把确认的最新时间戳写回复核文件，然后在一个数据库事务内统一发布整批知识，每批最多 50 条。任何条目过期，整批发布回滚；已经保存的人工修订仍保留，尚未进入知识库。

连接中断不能证明写入失败。脚本不会自动重试写入；请先到管理页面核对。成功发布后，复核文件更新知识版本，并将 `reviewed` 复位为 `false`，避免意外重复发布。

## 4. 实现与限制

- Flyway V78 新增课程反馈来源、当前知识状态和不可变发布版本表，兼容 MySQL 与 SQLite；V79 提供共享课程实体。
- 发布只接受当前 `RESOLVED` 的人工修订，且答案必须与已保存修订一致。并发发布用期望版本和数据库事务防止覆盖。
- 原反馈再次修订或撤销整理后，其旧发布版本不再进入检索，需重新确认发布。
- 静态项目帮助继续保留，动态问答与其合并排序。人工审核的问题按标题权重参与索引，降低仅因自定义标题而检索不到的情况。
- 动态检索每次最多读取最近 1000 条当前可见知识；尚未引入长期缓存，避免撤回和权限变化后仍使用旧结果。大规模知识量下可继续演进为按作用域、版本缓存和向量索引。
- AI 润色使用现有模型配置，有并发上限、45 秒以内总超时及 256 KiB 响应上限，不执行工具或文件操作。
- 没有新增定时付费调用或自动微调。未配置 AI 服务时，人工核对、发布、版本记录和撤回仍可使用。
