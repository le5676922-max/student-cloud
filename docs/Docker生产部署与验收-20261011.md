# 学生云盘：Ubuntu / 阿里云 Docker + Nginx 部署与验收

本方案使用源码构建前端和后端，配套 MySQL 8、Redis 和 Nginx。仅部署 **一个后端实例**；Redis 不代表登录会话、Agent 队列已经具备多实例能力。本教程使用新建的容器数据库，不读取、迁移或删除开发电脑的数据库。

最新本地验证及尚未实测的上线边界见 [2026-10-12 业务修复与验收报告](业务修复与验收报告-20261012.md)。配置检查通过不能替代本教程的真实镜像构建、容器启动和服务器验收。

## 1. 仓库里已经提供的文件

| 文件 | 作用 |
| --- | --- |
| `docker/compose.production.yml` | 四个服务、内网、持久卷、资源限制、日志轮转、就绪检查 |
| `docker/.env.production.example` | 无真实密码的配置模板 |
| `docker/compose.https.yml` | 正式域名 HTTPS 的覆盖配置 |
| `frontend/Dockerfile.deploy` | Node 构建后交给公开 Nginx 镜像，不需要本机 dist |
| `frontend/nginx/*.conf` | SPA 页面刷新、接口/下载代理、上传流式转发、Agent SSE |
| `backend/Dockerfile` | Maven/JDK 21 构建，非 root Java 运行 |
| `scripts/deployment-smoke.mjs` | 只读部署验收，不创建账户或上传/删除文件 |

服务器只需 Docker Engine、Compose v2 和项目源码，不需要单独安装 Node、Java、Maven、MySQL、Redis。测试脚本使用 Node 18+，也可以用临时 Node 容器执行。镜像均来自公开仓库；服务器需要能访问 Docker Hub、npm、Maven Central 和依赖源。不要随意使用不可信镜像加速地址。

目前资源限制合计约 3.5 GiB，不含系统、构建进程和文件缓存。4 GiB 服务器内存可能偏紧，构建时建议顺序构建；调整资源限制后必须压测。这不是并发承载能力的保证。基础镜像使用版本标签，正式发布可在镜像实测后记录 digest，避免标签更新产生差异。

## 2. 检查 Docker 和端口

通过 SSH 连接服务器后执行：

```bash
# 检查 Docker 服务；如果权限不足，可在命令前加 sudo。
docker version
docker compose version

# 确认磁盘和内存余量，构建期间还会占用额外磁盘/内存。
df -h
free -h

# 查看 80/443 是否已被现有 Nginx/网站占用，不要停止其它项目。
sudo ss -lntp | grep -E ':80 |:443 ' || true
```

若 80 已被其它服务使用，可以先在配置里设置 `WEB_HTTP_PORT=8088` 和 `APP_ORIGIN=http://服务器IP:8088`。正式 HTTPS 的示例使用标准 443；不要未经检查抢占已有网站的端口。

阿里云安全组仅按需要开放 22（最好限制你的管理 IP）、80、443。**不要开放 3306、6379、8080**。Docker 端口发布可能绕过部分宿主机防火墙规则，因此安全组及绑定地址都要明确设置。临时 HTTP 调试仅允许自己的来源 IP，完成 HTTPS 前不要让真实用户通过明文输入密码。

## 3. 上传项目源码

例如把仓库完整上传到 `/opt/student-cloud`，进入项目根目录：

```bash
cd /opt/student-cloud
ls backend/pom.xml frontend/package.json docker/compose.production.yml
```

上传 `backend/src`、`frontend/src/public/presets` 等所有构建需要的源码，不要只传 jar 或只传前端 dist。本地的 `node_modules`、`target`、日志、`.codex-run`、数据库文件、本地 profile 和密钥文件无需上传。已提供 Docker 构建上下文排除规则。

## 4. 创建服务器配置，不把密码写进镜像

```bash
# 复制已经提供的模板；不会操作数据库。
cp docker/.env.production.example docker/.env.production
chmod 600 docker/.env.production
nano docker/.env.production
```

至少修改以下内容，不能保留 `REPLACE_...` 或 `YOUR_SERVER_IP`：

```dotenv
# 完整网站地址，不能有结尾 /；临时验证可先使用服务器 IP。
APP_ORIGIN=http://203.0.113.10
WEB_BIND_ADDRESS=0.0.0.0
WEB_HTTP_PORT=80

# 三个不同的随机密码。示例只是说明格式，不能使用本文的内容。
MYSQL_ROOT_PASSWORD=你生成的独立root随机密码
STUDENT_CLOUD_DB_PASSWORD=你生成的独立应用随机密码
STUDENT_CLOUD_REDIS_PASSWORD=你生成的独立Redis随机密码
```

可以分别执行 `openssl rand -hex 24` 生成每个密码。十六进制随机值避免 `$`、空格、`#` 的 `.env` 解析问题。不要把输出截图或发到聊天里。`MYSQL_ROOT_PASSWORD` 仅用于数据库管理；后端用 `student_cloud` 应用账户，只能访问项目自己的库。

配置文件存放在服务器，权限为 600，已由 `docker/.gitignore` 排除。Docker 管理员可以查看容器环境，因此服务器管理账户也必须可信。不要执行或公开输出完整 `docker compose config`、`docker inspect` 的环境信息；验证时使用 `config --quiet`。

QQ 邮箱注册/密码找回需要填写：

```dotenv
MAIL_ENABLED=true
MAIL_HOST=smtp.qq.com
MAIL_PORT=465
MAIL_USERNAME=你自己的发件QQ邮箱@qq.com
MAIL_FROM=你自己的发件QQ邮箱@qq.com
MAIL_PASSWORD=服务器上填写SMTP授权码
MAIL_CODE_SECRET=另一个openssl-rand-hex-32生成的随机值
```

QQ 的授权码不是邮箱网页登录密码。`MAIL_CODE_SECRET` 用于验证码安全处理，不要复用数据库或邮箱密码。没有配置邮件时保持 `MAIL_ENABLED=false`；不要假装注册/密码找回可以发信。AI 可先保持关闭；需要使用时填写 `TLGXY_CLOUD_AI_ENABLED=true`、供应商 API key、模型与 API 地址，具体模型可用性以你的供应商账户为准。

### 可选：启用纯扫描 PDF 的本地 OCR

后端镜像包含 Tesseract 英文及简体中文语言包，默认关闭。需要时在 `docker/.env.production` 设置：

```dotenv
STUDENT_CLOUD_OCR_ENABLED=true
STUDENT_CLOUD_OCR_LANGUAGE=chi_sim+eng
STUDENT_CLOUD_OCR_MAX_PAGES=10
STUDENT_CLOUD_OCR_DPI=120
STUDENT_CLOUD_OCR_MAX_CHARS=60000
STUDENT_CLOUD_OCR_PAGE_TIMEOUT_SECONDS=15
STUDENT_CLOUD_OCR_TOTAL_TIMEOUT_SECONDS=90
```

重新创建后端容器后生效，不调用图片模型 API。只有 PDF 文字层完全为空才自动 OCR；混合 PDF 仍索引可提取文字，不自动补识别其中图片。单文件仍为 5MB 上限，扫描页数/字符覆盖会显示在索引说明中。图片边长和像素、单页/总时限以及并发均有限制，超限会提示拆分资料。OCR 的图片解码和页面渲染仍消耗 CPU/内存，建议先在小规模样本上测试，不要把页数/并发盲目调高。手写、图表、模糊扫描以及复杂排版结果必须人工校对。

OCR 临时图片仅落在容器 `/tmp`，逐页/请求结束删除，不保存在 Redis，也不通过 Agent 工具传给模型。非 Docker 部署需要管理员安装 Tesseract，并填写可信绝对可执行路径；不支持由用户指定命令或脚本。繁体 `chi_tra` 可配置但本镜像未安装该语言包，需自行增装后才能使用。

### 可选：配置独立嵌入模型用于语义检索

语义嵌入默认关闭，未配置时继续使用关键词检索。它与聊天模型是两套独立配置，不能把仅支持聊天接口的密钥当成嵌入服务。配置前确认供应商官方文档支持标准 `POST /embeddings` 和 `encoding_format=float`：

```dotenv
STUDENT_CLOUD_EMBEDDING_ENABLED=true
STUDENT_CLOUD_EMBEDDING_BASE_URL=https://你的兼容供应商地址/v1
STUDENT_CLOUD_EMBEDDING_API_KEY=在服务器填写独立嵌入服务密钥
STUDENT_CLOUD_EMBEDDING_MODEL=供应商实际支持的嵌入模型
# 必须与模型实际返回维度一致；可设范围32–4096，不是越大越好。
STUDENT_CLOUD_EMBEDDING_DIMENSIONS=1024
STUDENT_CLOUD_EMBEDDING_MIN_SIMILARITY=0.25
```

base URL 只允许 HTTPS，不能包含账号、查询参数或 fragment；客户端不跟随跳转，不自动重试，不记录供应商响应原文或密钥。资料正文片段会发送到该外部嵌入供应商，**仅在用户同意、资料允许外传并确认隐私政策后启用**；这与默认本地关键词检索/本地 OCR 的边界不同。

每资料最多覆盖前64段，每段最多700字符，每次网络请求最多16段；整次资料嵌入共享10秒总请求期限，最多并发2个任务，单次响应上限2MiB。向量维度、索引完整性、有限数值与非零归一化均验证；不匹配或服务失败会明确退回关键词检索，不伪造可用语义结果。更改模型、地址或维度后需重新索引资料，不能把不同模型向量混在一起计算相似度。具体覆盖以页面索引说明为准，不代表全部长文档都已语义索引。

## 5. 验证配置、构建、启动

以下每条命令都在项目根目录执行，必须显式指定同一个 env 文件和 Compose 文件：

```bash
# 仅检查配置，不打印展开后的密码。
docker compose --env-file docker/.env.production -f docker/compose.production.yml config --quiet

# 先顺序构建后端和前端，减少构建时的峰值内存压力。
docker compose --env-file docker/.env.production -f docker/compose.production.yml build backend
docker compose --env-file docker/.env.production -f docker/compose.production.yml build frontend

# 创建服务并等待就绪。不会使用本机已有 MySQL，而是创建新命名卷。
docker compose --env-file docker/.env.production -f docker/compose.production.yml up -d --wait --wait-timeout 300

# 检查服务状态，4 个服务都应 healthy。
docker compose --env-file docker/.env.production -f docker/compose.production.yml ps
```

第一次启动 MySQL 创建空库，后端 Flyway 自动执行数据库迁移，随后才会就绪。后端就绪检查除了 Java 启动状态，还会检查数据库连接；它只接受容器内部 loopback 请求，不开放给浏览器。Redis 启动时使用密码，后端共享限流采用故障关闭策略；Redis 故障时邮件发送可能暂时被拒绝，而不是绕过限流。

Redis 缓存和限流共用实例采用 `noeviction`，避免内存不足时提前驱逐计数。Redis 不持久化，重建会重置短期限流状态；验证码及业务数据仍保存在 MySQL。内存满时应排查键数量/过期时间或增加资源，不应改为随意淘汰计数来绕过限流。

容器间地址是 `mysql:3306`、`redis-cache:6379`、`backend:8080`，不是 `localhost`。MySQL、Redis 只在 Docker 内网；后端额外连接外网网络，用于访问邮件、AI 和对象存储。网络 `10.77.0.0/24` 如与服务器网络冲突，需要同时修改 Compose 子网、Nginx 固定 IP 和后端可信代理 CIDR，不能只改其中一项。

## 6. 首次初始化与存储空间

浏览器打开 `http://服务器IP`，空数据库会进入初始化页面。通过网页创建全局管理员并设置强密码，没有预置通用登录密码。初始化完成后登录；不要向外公开尚未初始化的站点，避免他人先创建管理员。

数据库和上传文件分别保存在 Docker 命名卷：

- `student-cloud_mysql-data`：MySQL 表、用户、设置、知识库与任务记录。
- `student-cloud_business-data`：工作空间共享文件 `/app/data/workspaces`、运行日志。
- `student-cloud_upload-staging`：本地分片续传的私有暂存目录 `/app/upload-staging`，不混入用户可浏览目录；过期任务按暂存策略清理。

分片续传默认总暂存配额20GiB，按文件大小约2倍预留（分片与拼接），配置 `STUDENT_CLOUD_UPLOAD_STAGING_QUOTA_BYTES` 可调整；这不是用户最终文件容量配额。过期时间固定24小时，后台每15分钟分批清理，每个用户最多8个未完成任务。暂存目录权限700、UID10001拥有，不能位于任何本地云盘根目录之下，也不能包含云盘根目录；不要把 `/app` 或 `/app/upload-staging` 配成可浏览存储源。普通容器重建保留暂存卷，以便恢复符合条件的未完成上传。

本地存储源的新增、修改、复制、连接预检以及启动时的旧配置初始化都会检查上述双向隔离，不允许通过符号链接或目录联接把私有分片变成公开文件。即使关闭分片续传，此检查也不关闭：暂存卷可能仍有尚未过期的旧分片。不安全的旧本地存储源将拒绝初始化，需要管理员调整路径；不会自动移动或删除数据。不要为了通过检查而删除私有卷或降低目录权限；应使用与云盘根互不包含的独立路径。

浏览器对本地大文件分片使用 WebCrypto SHA256，正式网站必须配置 **HTTPS**；`localhost/127.0.0.1` 是浏览器开发例外，公网 HTTP 不是安全上下文。公网 HTTP 上无法续传时会给出明确提示，不应绕开校验或声称续传可用。当前分片续传仅支持本地代理上传，不能推断全部云存储协议都支持断点续传。

Nginx 对 `/api/uploads/resumable/<任务ID>/chunks/<分片编号>` 单独限制正文4MiB，先完整缓冲再转交后端，减少慢速客户端占用后端分片上传槽位。分片正文读空闲超时15秒（不是整个分片限时15秒）；Nginx只读容器使用私有 `/tmp` 64MiB tmpfs，分片全局最多12个、同一客户端IP最多4个缓冲请求，最坏正文约48MiB，超额返回429。413仍表示分片正文过大，不会改成成功响应。前端遇到中断或繁忙后，可重新选择原文件续传；不调整分片大小绕过校验。普通整文件上传和 Agent SSE 仍不缓冲。上述限制在 HTTP 调试与 HTTPS 正式配置中一致；共享公网出口下需要根据实际负载适当调整并发限制和 tmpfs，而不是直接取消上限。

普通停止/重建容器不会删除这两个卷。**不要执行 `docker compose down -v`、`docker volume prune` 或手工删除卷**，除非明确准备丢弃对应数据。本文不要求保留开发电脑上的数据库，但服务器开始提供真实服务后，文件与数据库卷仍是业务数据。

在网页添加“本地存储源”时填容器路径，例如 `/app/data/workspaces/...`，不是 Windows 的 `C:\...`。自动创建的工作空间已经使用持久化根目录。若另挂载宿主机目录，需要提前创建目录并赋给 UID/GID `10001:10001`，不要用 `chmod 777` 解决权限。只挂载计划使用的文件目录，不挂载整个服务器 `/` 或 `/root`。

站点域名设置填写你的完整公网地址，便于生成正确下载链接。对象存储浏览器直传还需在云厂商控制台配置精确的 CORS 域名，保存连接不会自动替你修改云端权限。

## 7. 正式使用 HTTPS（容器内 Nginx）

准备域名，将 A 记录指向服务器。到可信证书服务签发该域名的证书，获得完整链 `fullchain.pem` 和私钥 `privkey.pem`。此步骤不依赖本文自动申请证书；证书续期由管理员安排。

```bash
# 只创建证书目录，不输出私钥。
mkdir -p docker/certs
chmod 700 docker/certs
# 用 SFTP 将 fullchain.pem 和 privkey.pem 放入 docker/certs 后执行：
chmod 600 docker/certs/privkey.pem
chmod 644 docker/certs/fullchain.pem

# 编辑 env：APP_ORIGIN=https://cloud.example.com，WEB_HTTP_PORT=80。
nano docker/.env.production

# 同时加载基础配置和 HTTPS 覆盖配置，80 会跳转到 443。
docker compose --env-file docker/.env.production -f docker/compose.production.yml -f docker/compose.https.yml config --quiet
docker compose --env-file docker/.env.production -f docker/compose.production.yml -f docker/compose.https.yml up -d --wait --wait-timeout 300
docker compose --env-file docker/.env.production -f docker/compose.production.yml -f docker/compose.https.yml exec -T frontend nginx -t
```

以后维护 HTTPS 站点时，命令均保留两个 `-f`，避免误退回 HTTP。证书替换后先 `nginx -t`，成功再 `nginx -s reload`。不要把证书目录传进 Git。不要直接在 HTTP 页输入真实账户凭据。

## 8. 只读接口与路由验收

```bash
# 检查 Nginx 配置；不会更改文件或数据库。
docker compose --env-file docker/.env.production -f docker/compose.production.yml exec -T frontend nginx -t

# 有 Node 18+ 时运行；HTTPS 站点把地址改成自己的域名。
node scripts/deployment-smoke.mjs http://127.0.0.1

# 没有 Node 时用公开临时镜像，只读挂载项目；Linux host 网络用于访问本站。
docker run --rm --network host -v "$PWD:/work:ro" -w /work node:22-alpine node scripts/deployment-smoke.mjs http://127.0.0.1
```

脚本检查登录页、业务页、管理页直接刷新能加载；公开启动接口返回 JSON；未登录的管理/下载/文件接口拒绝访问；私有就绪端点不可公网访问；不存在的静态资源返回 404。**它不代替真实登录、上传、SMTP、云存储或并发压测。** HTTPS 配置会把 HTTP 请求重定向，因此验收脚本应使用 `https://你的域名`，不是 HTTP。

手工继续验收：全局管理员登录、普通空间管理员注册、邀请码加入、空间名待审批、邮箱密码找回、上传/下载/删除临时测试文件、移动后知识库路径联动、Agent 预览确认、流式输出、用户禁用后立刻拒绝访问。只在单独测试空间执行变更操作，不要拿正式文件做破坏性测试。

Nginx 已代理固定的 `/api`、`/user`、`/admin`、`/file`、`/pd`、`/d`、`/s`、`/directlink`、`/open115` 等路由。`/admin` 的 HTML 页面导航与 JSON 接口分开处理。SSE 响应关闭缓冲，上传关闭请求缓冲，非幂等请求不自动重试。若自行修改后台的“直链前缀”，必须将新前缀加入 `frontend/nginx/routes.conf`，再重建前端，否则会被误判为 Vue 页面。

## 9. 查看故障，更新和停止

```bash
# 日志可能含业务信息，只在管理终端查看，不要公开整份日志。
docker compose --env-file docker/.env.production -f docker/compose.production.yml logs --tail 100 backend
docker compose --env-file docker/.env.production -f docker/compose.production.yml logs --tail 100 mysql
docker compose --env-file docker/.env.production -f docker/compose.production.yml logs --tail 100 frontend

# 获取新源码后重新构建；数据库迁移是升级的一部分，不能任意跳过。
docker compose --env-file docker/.env.production -f docker/compose.production.yml build backend frontend
docker compose --env-file docker/.env.production -f docker/compose.production.yml up -d --wait --wait-timeout 300
# 后端重建后重启 Nginx，让静态 upstream 重新解析新的 backend IP。
docker compose --env-file docker/.env.production -f docker/compose.production.yml restart frontend

# 只停止服务，保留卷；重新 up -d 即可启动。
docker compose --env-file docker/.env.production -f docker/compose.production.yml stop
```

HTTPS 用户以上命令都附加 `-f docker/compose.https.yml`。HTTP 500 先看后端根因，不能只刷新前端；502/504 检查后端是否 healthy、数据库/Redis 是否可达。`using password: NO` 表示密码未传入，检查 env 文件和容器重建是否完成。已有 MySQL 卷不会因修改 `MYSQL_PASSWORD` 自动修改库中账户密码；更换密码须按数据库正常改密流程同步应用环境，不能靠删卷解决。

4xx 上传失败检查后端 512MB 限制、云端权限与 CORS；413 检查 Nginx 上传限制。Agent 问答成功但没有流式展示，检查是否额外套了另一层会缓冲 SSE 的反向代理。多层代理时不要直接信任用户提供的转发头，需要重新明确可信链。

## 10. 本轮验证边界

本机可找到 Docker CLI / Compose，完整 Compose 的 `config --quiet` 检查通过；但本机 Linux Docker 引擎管道尚未就绪，因此没有完成真实镜像构建、Compose 启动或 Nginx 运行验收，也没有访问现有 MySQL 数据。已增加部署契约测试、YAML 静态解析、私有 readiness 单元测试，以及隔离 CI：三个独立 MySQL 测试库、专用 Redis 和完整 Compose 路由冒烟。**CLI/配置可用和单元测试不能当作目标服务器部署通过；CI 也需要实际运行成功才算完成对应验收。**

多人容量需要在隔离测试空间进行阶梯压测，记录 p95/p99、错误率、MySQL 慢查询/连接等待、Redis 键数和内存、CPU/内存及对象存储延迟，不能根据“已安装 Redis”推断人数上限。S3快速目录浏览的 continuation token 是单实例内5分钟有效的游标，实例重启需重新进入首屏；它不代表所有提供商都支持原生分页或已知总条数。暂不使用 `--scale backend`，直到登录会话、Agent 队列、目录游标和进程内状态完成多实例设计与测试。

## 11. SFTP 主机指纹安全升级与连接预检

旧版本 SFTP 跳过主机密钥校验，本轮改为每个会话严格校验管理员核实的 SHA256 指纹。**现有 SFTP 存储源必须补填“SSH 主机 SHA256 指纹”后才能重新连接**；缺失或不匹配均拒绝连接，不自动信任首次密钥，不降级为 `StrictHostKeyChecking=no`。

在目标 SFTP 服务器的可信控制台执行（不是项目服务器自动扫描陌生主机）：

```bash
# 查看目标服务器实际使用的 SSH 公钥指纹，例如 Ed25519 主机密钥。
# 这里只读取公开 .pub 文件，不要读取或传输私钥文件。
ssh-keygen -l -E sha256 -f /etc/ssh/ssh_host_ed25519_key.pub
```

把其中 `SHA256:...` 值通过可信管理员/控制台渠道核实后填到存储源设置。它必须对应 SFTP 连接实际协商的主机密钥；服务器同时有 RSA/ECDSA/Ed25519 时，不同公钥的指纹不相同。`ssh-keyscan` 只能取得网络对端声称的公钥，**不能单独证明其可信**，不能把未经核实的扫描结果直接作为信任来源。

主机换机或正常轮换密钥时，先从可信渠道确认新指纹，再更新存储源并重新连接。意外不匹配先暂停使用并核实，不要关闭验证或盲目覆盖旧指纹。指纹是公开信息，但 SSH 私钥、用户密码仍必须保密。

添加存储源的独立只读预检目前支持本地目录、S3兼容桶以及公网 **HTTPS Basic/无认证 WebDAV**。WebDAV 仅请求 `PROPFIND Depth:0` 的目录元数据，不列子文件，不创建目录/上传/删除；连接前公网 DNS 校验且固定校验后的 IP，禁止内网、云元数据、重定向、URL内凭据与外部 XML 实体读取。它不验证上传/删除权限，也不证明所有日常操作均通过。

SFTP 独立预检仍明确不支持，不会用关闭主机校验的方式假装通过；正常 SFTP 业务连接已严格要求可信 pin。FTP 独立安全预检仍不支持，明文 FTP 不推荐用于公网；不要因为普通驱动支持 FTP 就推断密码传输和被动数据连接都已加固。没有使用任何私人真实 FTP/SFTP/WebDAV 账号进行本轮验证。
