# 小芽长期记忆：使用与部署（2026-10-22）

## 现在能记住什么

小芽新增按账号保存的长期记忆，用于记住**用户明确提供的偏好和背景**，例如所学课程、解释深浅和回答习惯。数据由后端保存在数据库中，不依赖浏览器本地存储或 Java 进程内缓存，因此正常保存后刷新页面、重新登录或重启服务不会丢失。

这不是把全部聊天永久存档，也不是把旧文件内容永久加入知识库。附件、工具结果、模型推测、历史消息不会被自动写成记忆；文件访问、课程证据及自动化任务仍走现有实时校验和页面确认。

## 使用方法

1. 登录，打开小芽。
2. 点击助手顶部的“长期记忆”图标，查看当前账号已保存的条目。
3. 在面板中填写偏好并保存，或者直接在聊天里发送：

   ```text
   请记住：我正在学习 Java，讲解时先给结论，再给一个简短示例。
   ```

4. 只有服务端保存成功后，助手才会返回“已记住”。这个明确保存操作不需要额外模型调用，即使聊天模型暂未配置也能保存。
5. 后续提问时，服务端按本次问题与近期条目挑选有限记忆作为背景。当前明确要求优先于旧偏好；是否真正遵循偏好仍受所配置模型的能力影响。

可以直接编辑单条记忆，保留原 ID、创建时间与位置，不再需要先删后加。也可以在面板按关键词筛选、删除单条记忆、确认清空全部，或关闭“使用长期记忆”。关闭会暂停后续自动召回和新增/编辑，但保留已有条目，本人仍可查看和删除。

聊天中发送“查看我的记忆”或“你记住了什么？”可直接查看数量和最近至多 5 条摘要，不请求模型；完整内容在面板中查看。保存建议使用明确的“请记住：内容”格式。对“记住功能怎么用？”这类提问，不会自动保存为记忆。

编辑时会带上点选条目时的原文。如果其他窗口已经修改过这条记忆，将拒绝覆盖并提示刷新；同一保存已成功后的重复提交保持幂等。明确的长度、敏感内容和重复内容校验失败可保留草稿，修改后再保存；超时、未知结果和并发冲突需先刷新确认状态，不自动重试写入。

清空对话**不会**删除长期记忆；反过来，删除记忆也不会擦除当前聊天窗口中的旧消息。希望两者都清除时，请分别操作。已经发送给模型的请求和当前正在处理的上下文不能通过删除记忆追回。

## 存储与隐私边界

- 每账号最多 **50 条**，每条最多 **500 个字符**。达到上限后不会自动删除旧记忆，需要本人整理。
- 每轮最多选择 **6 条**，序列化上下文不超过 **2500 个字符**；相关性使用本地关键词/中文双字匹配与近期排序，不调用 embedding 或额外总结模型。
- 以用户主键读取单行受限 JSON，使用版本条件更新，避免两个窗口相互覆盖或突破条数限制。发生冲突时提示刷新，不自动用旧快照重试。
- 本轮新增的持久层使用 MySQL；测试环境也有对应 SQLite 迁移。Redis 不是记忆的唯一存储，不需要为了本功能额外启动 Redis。
- HTTP 接口不接受用户指定的归属账号；普通用户、空间管理员和全局管理员都只能通过这些接口管理自己的记忆。账号删除时同步清理关联记录。
- 不要保存密码、QQ 邮箱授权码、验证码、API 密钥、令牌、文件链接或服务器路径。后端会拦截常见敏感格式和明显越权指令，但这不是完整的敏感信息识别系统，不能保证识别任意秘密。
- 记忆在业务数据库中保存，**本轮没有增加静态加密**。有数据库管理权限的人仍能读取业务表；应继续限制数据库访问和备份权限。
- 启用后，被选中的记忆会随提问发送给当前配置的模型服务，不是“只存在本机、绝不出网”。关闭记忆只影响后续读取，不能撤回已经提交到服务商的内容。
- 记忆作为不可信的用户背景消息，不作为 system 规则、权限、课程引用或任务确认。没有增加模型可调用的记忆写入/确认工具。

## 前端管理

只在小芽窗口顶部加入一个管理入口和独立面板，保留小芽形象、动画、登录页及现有文件操作。面板支持计数、开关、添加、直接编辑、关键词筛选、逐条删除、清空二次确认和失败恢复。筛选仅在当前账号已加载的至多 50 条中执行，不请求数据库或模型；“清空全部”始终针对全部记忆，不只是筛选结果。

账号或空间切换、退出及组件卸载会中止旧面板请求并清除显示；即使底层请求不响应取消，迟到结果也不能写到新账号面板。记忆正文按普通文本渲染，不作为 HTML 执行。

## 后端接口

所有接口要求有效登录并重新检查当前账号状态，统一返回项目原有 `AjaxJson` 包装。归属账号来自登录身份，而非请求字段。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/ai/memories` | 当前账号开关、容量限制和记忆列表 |
| POST | `/api/ai/memories` | 保存 `{ "content": "偏好或背景" }`；重复内容幂等 |
| PUT | `/api/ai/memories/{id}` | 修改 `{ "content": "新内容", "expectedContent": "编辑前原文" }`，保留 ID 和创建时间 |
| PUT | `/api/ai/memories/settings` | 更新 `{ "enabled": true }` 或 `false` |
| DELETE | `/api/ai/memories/{id}` | 删除自己的指定条目 |
| DELETE | `/api/ai/memories` | 清空当前账号记忆，保留开关 |

状态为 `{ enabled, maxEntries, maxChars, items }`，每条包含 `{ id, content, createdAt }`；`createdAt` 是 ISO 时间字符串。写入、删除和设置也返回更新后的状态。现有普通、附件及 SSE 聊天接口的请求和结果格式不变。

编辑接口的 `expectedContent` 对旧调用方是可选字段，但新版面板始终携带。自行接入时也应发送该字段，才能识别“编辑页面早已过时”的冲突；数据库版本 CAS 仍负责保护提交过程中的并发更新。两者不能相互替代。

## 部署与升级

新增 Flyway **V73**：`V73__private_ai_long_term_memory.sql`，分别位于 `backend/src/main/resources/db/migration-mysql/` 和 `migration-sqlite/`。不修改 V1–V72，不重建或清空现有库。

重新打包并启动新后端后，Flyway 自动创建 `ai_long_term_memory` 表。迁移账号需要建表和外键权限；MySQL 用户表需要使用 InnoDB，且数据库保存数据的目录或 Docker 卷必须持久化。不要删除 MySQL 数据卷来“重新启动”，否则记忆和其他业务数据都会丢失。已经使用首版 V73 的环境升级编辑/筛选等后续功能，只需更新程序，不新增表迁移，也不需要清空记忆。

前端需同时更新并重新构建，才会显示管理入口。只刷新使用旧代码的部署、或仅启动旧 JAR，不能启用此功能。本轮不自动推送 GitHub，也不自动升级当前业务库。
