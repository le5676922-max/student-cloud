# AI 转人工客服：使用与部署

## 成员如何联系人工

- 在小芽中直接说“人工服务”“转人工”，或点击“AI 未解决？转人工客服”。AI 判断需要人工核实、用户反馈上轮未解决或模型连接失败时，会在对话内提示是否转人工；这些建议不会自动创建客服会话。
- 真实模型回答下方的“没有解决？”是单独的改进反馈入口，旁边注明会提交本轮问答。点击后将本轮问题和回答提交给全局管理员复核，同时显示转人工确认卡片；取消转人工不会撤回已提交反馈。反馈记录与人工客服会话独立，详细范围见 [AI 回答反馈与人工整理](AI回答反馈与人工整理说明-20261024.md)。
- 提示卡片显示可编辑的问题描述，通常预填最后一个用户问题。检查或改写后，点击“确认转人工”才发起会话。取消或继续问 AI 不会创建客服会话。没有历史问题时预填“我需要人工客服协助”，可以直接确认或补充描述。
- 确认后在同一个助手窗口等待接待、补充问题并接收全局管理员回复；不跳转页面。返回 AI 保留原 AI 对话，不会结束人工会话；可从助手入口返回人工聊天，点击“结束会话”需要再次确认。
- 人工客服会话只发送卡片中确认的文本和人工聊天中主动输入的内容，不自动导入 AI 的其他对话、附件、长期记忆或云盘文件；用户主动提交的本轮问答反馈另行保存。用户可以从云盘账户菜单的“人工客服”进入独立 `/support` 页面，手机菜单同样提供入口，不需要先打开 AI。
- 客服就是全局管理员；成员之间看不到对方的客服会话，空间管理员也只能查看自己作为用户发起的会话，不能接待别人的会话。
- 人工可能暂时不在线。消息保存成功表示服务器已持久化，不表示管理员已读；稍后可以返回页面查看回复。WebSocket 断开时可手动重连或刷新，发送失败时检查草稿与发送状态，不要误以为消息已成功。

## 全局管理员如何处理

进入全局后台的“人工客服”，按等待接待、处理中、已关闭筛选。选择具体会话后接待并回复；问题解决后关闭。关闭的会话保留历史，成员需要新的帮助时可再次发起会话。客服权限不赋予代替用户执行文件操作、确认 Agent 任务或读取未主动提供的私人资料的能力。

## 传输与持久化

客服文本通过现有已认证 HTTP 接口持久化，WebSocket `/ws/support` 负责实时变更通知，页面再读取自己有权限的会话增量消息。刷新、重连或服务重启不会以 WebSocket 内存记录替代数据库历史。

AI 对话结果新增可空 `supportSuggestion: { reason }`。模型可调用 `suggest_human_support` 表达需要人工协助，该工具只产生建议，不创建会话、不访问客服数据；前端展示用户确认卡片。明确的转人工请求和有上一轮回答的未解决反馈可由服务端直接识别，无需模型密钥。全局管理员不提供向自己转人工的建议。普通答疑不会固定附带转人工卡片，用户明确拒绝时不会强行转接。

新增的 V74 迁移只创建 `support_conversation` 和 `support_message` 表。每个成员最多一个活跃会话；结束后可发起新会话。发送携带请求标识，相同账号以同一标识重试相同消息只保存一次。页面内存窗口最多展示最近载入的 500 条消息，达到上限会提示，不代表数据库删除了更早记录。不要发送密码、验证码或 API 密钥。

浏览器先使用现有登录身份领取短时、一次性握手票据，再建立连接；长期登录 Token 不写进 WebSocket URL。连接需要同源校验与后端授权，不能因为知道会话 ID 就订阅其他成员。票据、在线连接属于单实例内存状态；本轮按现有单后端部署设计。增加后端副本时，需要先实现共享票据和跨实例通知，不能仅添加 Redis 容器就宣称完成集群客服。

票据有效期 30 秒且只能使用一次；每个账号最多 4 个未消费票据和 4 条实时连接，单后端最多 256 条客服实时连接。连接断开后历史仍由 HTTP 接口读取。页面在服务器策略拒绝后停止自动重连，其他连接错误采用有限次退避，避免无休止申请票据。实现基于 [Spring 原生 WebSocket API](https://docs.spring.io/spring-framework/reference/web/websocket/server.html)，发送使用有界并发会话封装。

## Vite 本地开发

`frontend/vite.config.ts` 为 `/ws/support` 配置 `ws: true`，目标沿用 `CLOUD_API_TARGET`（默认 `http://127.0.0.1:8080`）。代理仅在原始浏览器 Origin 与 Vite 访问地址同源时，才将上游 Origin 转成后端地址；跨源或缺少 Origin 的升级请求会被拒绝，不能无条件洗白任意 Origin。

## Docker + Nginx

前端 Nginx 共用的 `routes.conf` 已增加精确的 `/ws/support` 规则，转发到 `cloud_backend`，使用 HTTP/1.1，并保留 `Upgrade`、`Connection: upgrade` 和前端 Host。该路径不回退到 Vue HTML 页面、不缓冲，读取超时为 90 秒；页面发送心跳维持连接。

上线必须重新构建前后端镜像，更新到包含新迁移和新代理规则的版本。沿用现有持久化 MySQL 数据卷，不需要重建业务数据库。外层负载均衡、CDN 或阿里云网关也需开启 WebSocket 升级并设置足够空闲超时；若外层网关覆盖 Host/Origin，必须按实际域名校验，不能用 `*` 关闭来源限制。

HTTPS 网站必须使用 `wss://`，页面会根据服务地址选择协议，不应从 HTTPS 页面连接明文 `ws://`。Nginx 对握手路径关闭访问日志，避免记录一次性票据；不要把浏览器完整握手 URL 或私密登录 Token 贴到公开日志。

生产 Compose 已将 `APP_ORIGIN` 映射到后端允许的浏览器 Origin。请填写用户实际访问的精确地址，例如 `APP_ORIGIN=https://cloud.example.com`；非默认端口也必须包含，例如 `https://cloud.example.com:8443`，不要附加路径或填入 `*`。独立前后端部署使用 `TLGXY_CLOUD_CORS_ALLOWED_ORIGINS` 设置精确允许列表。HTTPS 在 Nginx 终止而上游为 HTTP 时，后端通过该明确允许列表识别真实 HTTPS 来源，不依赖任意客户端自报的转发头。

验证时至少覆盖成员 A/B 会话隔离、管理员接待回复、关闭后禁止新发言、相同消息 ID 重试不重复、连接失败与重连、过期／重放票据拒绝、账号停用后失效，以及 Nginx 真实升级转发。

## 本轮本地验证

- 后端全量 906 项：889 通过、17 项按环境条件跳过，0 失败；前端全量 626 项通过，类型检查和生产构建通过。
- 实际启动隔离后端，使用 HTTP 和原生 WebSocket 客户端验证成员发送、管理员通知／回复、成员收取、另一成员无通知、历史读取、关闭、消息去重、来源／票据重放拒绝和退出登录后现有连接失效。
- 上述完整链路另在新建的临时 MySQL 库运行通过，随后只删除该测试库；没有向业务库添加测试聊天记录。V74 在业务环境仅新增客服表。
- 新增客服帮助后又执行 66 项知识库与客服定向回归，均通过。没有调用外部 AI 服务或发送邮件。
- 本轮未进行浏览器视觉验收、真实 Nginx 容器升级转发验收或多人并发容量压测。代理已有静态契约和同源校验测试，但不能替代部署后的实际网关验收。
