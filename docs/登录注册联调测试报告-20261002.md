## 本地 UI 邮件测试支持

本地接收器：`.codex-run/auth-ui-smtp.mjs`，仅绑定 `127.0.0.1:1825`。支持 `EHLO`、`HELO`、`MAIL`、`RCPT`、`DATA`、`RSET`、`NOOP`、`QUIT`；连接空闲超时为 8 秒。正常退出时释放监听端口及已有连接。

接收器仅允许保留测试域收件人，如 `auth-ui-…@example.test`，从 MIME `text/plain`（含 base64、quoted-printable 和 multipart）提取 6 位注册验证码。接收数据写入 `.codex-run/auth-ui-mailbox.json`，结构为 `messages` 数组，每项含 `recipient`、`code`、`receivedAt`。控制台只输出监听端口和接收数量，不输出收件人、验证码或正文。该 JSON 为本机测试运行产物，不应纳入报告或发布材料。

从项目根目录启动：

```powershell
node .codex-run/auth-ui-smtp.mjs
```

联调期间已运行此接收器，收到五封仅在本机接收的保留测试域邮件。其中四个账号由浏览器注册，另一个通过测试前端代理创建，用于追加复测拒绝后的自动刷新。独立测试后端的邮件主机为 `127.0.0.1`、端口 `1825`，关闭认证、SSL 和 STARTTLS；这只适用于显式配置的回环地址测试接收器，生产 QQ 邮箱继续使用认证和加密连接。没有向其他真实收件人发送测试邮件。

## 联调中修复的问题

- 登录凭据校验绑定已解析用户 ID，不能由客户端伪造该 ID，避免账号改名等情况导致校验对象与登录对象不一致。
- 兼容旧账号时防止邮箱/系统 ID 与手工用户名冲突，并增加用户名唯一约束。
- 验证码错误次数和成功消费独立提交，不会随后续注册失败被事务回滚。
- 静态用户服务引用与静态授权缓存会跨 Spring 上下文串用，已改成当前上下文/实例，保留缓存能力。
- 确认密码随密码输入变化即时重验证，清除残留不一致提示。
- 将待审批/未通过与普通停用区分；批准和拒绝都触发成员列表刷新。
- 新增状态列表查询只对当前页最多 20 个用户批量查询一次，不逐个用户查询数据库。

最终全量测试前曾有一个新增单元断言未兼容 MyBatis 对保留字段 `role` 的反引号转义。修正断言后，三个针对性用例和上述完整 210 项回归均通过；对应真实 MySQL 集成用例未出现该断言问题。没有通过跳过失败用例来获得通过结果。
