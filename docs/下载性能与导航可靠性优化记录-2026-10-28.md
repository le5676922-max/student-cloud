# 下载性能与导航可靠性优化记录

## 本轮范围

本轮修改本地开发项目，保留现有界面、账号权限和服务拆分，不修改已经部署的网站，也不推送 Git。优先处理有复现依据的导航问题，以及下载时长时间没有保存反馈的问题。

## 下载链路结论

独立内容服务的下载接口已经通过 `InputStreamResource` 流式返回文件。网关为文件下载单独配置了流式路由，独立部署的 Nginx 代理也已经关闭响应缓冲，没有配置下载限速。因此本轮没有盲目增加后端实例、取消授权检查或提高存储连接数。

前端原来通过 Axios 先接收完整 Blob，再创建下载链接。用户需要等到整份文件接收完，才能开始保存；同时每个任务都会保留完整文件数据。

新路径在安全上下文、支持 File System Access 且存在有效用户操作的浏览器中，先选择保存位置，再使用原有认证请求逐块写入文件。其他浏览器保留 Blob 下载方式。永久登录令牌不会加入下载 URL，不会通过公开文件链接绕过权限。

“更快开始保存”和“公网传输速率更高”是不同指标。本轮优化消除前端整文件缓存的等待，并降低流式路径的应用内存占用；不能以此承诺超过服务器公网带宽、远程存储服务或客户端网络的吞吐上限。

### 下载完整性

- 保留每文件 50 MiB 和最多两个同时下载的当前资源预算。
- 开始下载时固定文件名和目录记录中的大小，检查响应类型、响应长度和实际接收字节数；错误页面不会被当作文件保存。
- 文件发生变化、提前结束、超限、磁盘写入失败或网络失败时，中止临时写入，不将不完整文件提交为成功结果。
- 保存选择取消后不发送下载请求。流式请求开始后不自动重新发送 Blob 请求，避免重复传输。
- 切换账号、目录、存储源或失去权限时取消当前下载，并释放请求、读取器与写入资源。
- 流式保存使用非阻塞百分比提示，实际提交文件成功后才显示“已保存”；取消或失败会关闭进度提示。

另创建一份独立的 32 MiB 随机文件，通过同一个 Vite 代理，使用实际安装的 Axios fetch adapter 和生产 `writePrivateDownloadStream`，交替执行 Blob 与流式保存各三次。文件 sink 用 Node 临时文件模拟 write/close/abort，完成后逐个校验磁盘文件 SHA-256。

## 课程导航修复

课程接口返回数字 ID，而 URL 查询参数是字符串。原来的严格相等比较会导致访问 `/courses?course=8` 时选中第一门课程，刷新及浏览器历史也可能定位错误。

修复仅在 URL 边界统一 ID 的字符串比较，业务状态和接口调用保留后端原始 ID。新增实际 Vue 页面回归，覆盖数字 ID 的直达、刷新和查询参数切换，同时保留已有字符串 ID 的兼容性。

## 跨云盘历史导航修复

从一个云盘子目录跳到另一个云盘，再使用浏览器前进或后退时，路由会更新存储源下拉框。原有下拉框 watcher 将这次同步误认为用户主动切换，再跳转到该云盘根目录，导致子目录丢失并增加一次目录请求。

现在只有下拉值与当前路由的存储源不同时，才发起主动切源跳转。路由同步只更新下拉框，不发出第二次导航。新增真实 composable 回归，覆盖嵌套目录的跨源 Back/Forward，以及用户主动下拉换源仍进入根目录的行为。
