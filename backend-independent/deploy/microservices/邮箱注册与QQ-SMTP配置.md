# 邮箱注册、空间加入与 QQ SMTP

2026-10-26 · 适用于新的 Spring Cloud `cloud-platform-service`，不用于覆盖旧项目配置。

## 当前功能

- 用注册邮箱或系统分配的唯一账号 ID 登录，保留管理创建的原用户名登录。
- 邮箱验证后注册空间管理员：直接创建自己的工作空间，无需审核。
- 邮箱验证后注册成员：邀请码直接加入；空间名称提交申请，由该空间普通管理员审核。
- 普通管理员可连续创建多个邀请码，设置有效期/人数，也可设置长期有效或不限人数，并可撤销。
- 找回密码使用同一邮箱验证，成功后撤销所有旧会话。找回密码不会启用停用账号或绕过加入审批。
- 全局管理员不能通过公开注册产生；空间管理员只能处理自己空间的申请和成员。

个人目录、云盘权限和课程权限仍单独审批。加入空间不自动获得任何私有文件或课程资料访问权。

## 1. 私有配置

在新部署目录生成的 `.env` 中补充：

```dotenv
# 尚未准备好时保持 false，其它账号登录和管理功能仍可使用。
SC_MAIL_ENABLED=true
SC_REGISTRATION_ENABLED=true
SC_PASSWORD_RESET_ENABLED=true

# QQ SMTP 的 SSL 方式；这里是服务器端发件账号。
SC_SMTP_HOST=smtp.qq.com
SC_SMTP_PORT=465
SC_SMTP_USERNAME=你的发件QQ号@qq.com

# 填QQ邮箱生成的SMTP授权码，不能填QQ登录密码。
# 下方只是占位文字，不是可使用的授权码。
SC_SMTP_PASSWORD=替换为自己的SMTP授权码
```

生产模板固定开启 SMTP 身份验证、SSL 和服务器证书校验；不要关闭 TLS 以掩盖连接或授权错误。服务使用 Spring Mail，设置连接/读取/写入超时，避免邮件服务器异常长期占用请求线程。[Spring Boot 邮件配置说明](https://docs.spring.io/spring-boot/reference/io/email.html)

`.env` 不提交 Git，不打印到聊天或公开日志。代码不会自动读取旧项目秘密文件，不在数据库保存 SMTP 授权码。若手工直接运行 JAR，应把同名变量放入该平台服务进程的环境。

## 2. 使配置生效

新服务完成部署验收后，在对应的新微服务目录运行；本轮开发没有执行下面的 ECS 操作：

```bash
# 先静默检查配置，避免展开的密码出现在终端输出里。
docker compose -f compose.node-a.yaml config --quiet

# 仅重建容器配置，不需要改动用户文件或数据库。
# 新镜像中必须已经包含本轮注册功能；不要对旧站点目录执行此命令。
docker compose -f compose.node-a.yaml up -d --no-deps platform

# 查看健康状态。不要把 .env 或完整 docker inspect 输出公开。
docker compose -f compose.node-a.yaml ps platform
```

QQ 邮箱中需要开启 SMTP 并生成授权码。若发送失败，检查发件邮箱与授权码对应、ECS 到邮件服务的网络连接和服务日志中的公开错误；不要将授权码粘贴到反馈问题中。

## 3. 使用流程

1. 登录页打开注册，选择“空间管理员”或“成员”。
2. 管理员填写新空间名；成员选择邀请码或空间名。
3. 填写邮箱，获取6位验证码，填写密码与确认密码，提交。
4. 保存系统返回的唯一账号 ID。管理员和邀请码成员可登录；空间名称成员等待审核。
5. 空间管理员在管理页“加入申请”中批准或拒绝。待审核账号不能通过“启用账号”绕过这一步。

邀请码原文仅创建时显示一次，列表不返回原文。忘记邀请码可创建新的，并按需要撤销旧的。有效期和人数为空代表不限，不会被前端误判为已过期或已用完。

## 4. 验证码和隐私规则

- 验证码10分钟有效，60秒重发间隔，每邮箱每用途每日最多10次；5次错误后需重新获取。
- 注册与找回用途隔离，数据库只保存用途/邮箱/随机代次绑定的 HMAC 摘要，不保存明文验证码。
- SMTP发送不占数据库事务；验证码消费与账号/密码变更一起提交，失败不会留下半注册账号。
- 找回邮件的请求使用通用响应，不在接口中返回邮箱是否存在、验证码或密码。
- 平台限制邮件发送并发与客户端请求预算，发送失败后也保留冷却期。
- 成员资料、邮箱与加入申请只向有权限的本空间管理员提供，不向其它空间开放列表。

## 5. 本轮验收范围

账号管理、验证码、邀请、注册与成员批量查询的41项后端定向测试通过。临时 MySQL8.4.11、Gateway和四个服务进程配合本地 SMTP 接收器，完成实际发信协议、管理员注册、邀请码/空间名称加入、审批隔离、密码找回与会话撤销检查。没有向真实邮箱发信，也没有用QQ授权码做外部测试。
