# Student Cloud 智能服务

`cloud-intelligence-service` 是独立进程，默认本机 `18103` 端口。它装配 `cloud-assistant` 与 `cloud-tasks`，只依赖账号契约和服务客户端，不装配账号、课程、存储或客服实现。

## 业务与数据边界

- 自己拥有长期记忆、未解决反馈、审核知识及任务/Outbox 数据。
- 自有 V1/V2 迁移不创建或查询账号、空间、课程表，不保留跨服务数据库外键。
- 身份验证、账号状态与空间状态通过账号服务访问；记忆数量和反馈幂等使用本服务的 `sc_assistant_owner_guard` 锁，不能锁远端账号数据库。
- 课程知识通过内容服务的内部授权接口检查，检索前后均复核成员资格。内容服务不可用时返回 503，不能使用“允许访问”的降级结果。
- HTTP 响应保留当前反馈、记忆和知识整理接口；任务读/取消只返回本人的状态，不向浏览器返回 Worker 标识、fence 或原始工具参数。

共享数据库实例可节约 ECS 资源，但服务必须使用独立数据库和账号。该服务只接受 `student_cloud_intelligence` 或其下划线后缀库名，不读取旧项目密码，也不连接身份或内容数据库。

## 配置

| 配置 | 用途 |
| --- | --- |
| `SC_INTELLIGENCE_PORT` | 本服务端口，默认 `18103` |
| `SC_BIND_ADDRESS` | 默认 `127.0.0.1`，容器内绑定地址由部署显式指定 |
| `SC_INTERNAL_KEY` | 服务间调用密钥，与身份、内容服务一致；不是用户登录 Token |
| `SC_PLATFORM_URI` | SimpleDiscovery 中的账号/平台服务地址，默认本机 `18101` |
| `SC_CONTENT_URI` | 内容服务地址，默认本机 `18102` |
| `SC_INTELLIGENCE_DB_URL` | `mysql` profile 独立数据库地址 |
| `SC_INTELLIGENCE_DB_USER` / `SC_INTELLIGENCE_DB_PASSWORD` | 只拥有智能数据库权限的 MySQL 账号 |

服务间调用使用 Spring Cloud LoadBalancer 与 CircuitBreaker/Resilience4j，默认不自动重试，以免扩大授权依赖故障。权限拒绝在熔断执行结果之外解释，不会因一个成员无权访问而熔断其他成员；网络或服务端故障只返回不可用，不能降级为授权。精确连接/读取超时由共享客户端配置控制。外部 HTTP 请求仍需用户会话验证，服务间密钥不替代用户身份。

## 当前实施状态

已完成服务拆分代码；构建、实际启动与网关联调状态以根任务最新记录为准。知识仍是人工审核后的关键词检索；模型问答、向量索引、资料解析和任务执行器尚未完成。本服务不会自动读取已有 API 密钥、发送邮件或把私有知识发送给外部模型。
